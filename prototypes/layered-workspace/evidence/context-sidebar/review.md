不是对当前生产标签页的故障断言；生产 `LibraryTagCloud` 本来已在侧栏，原型此前没有同步。

## 优化要点

- 固定一套媒体库/快速访问导航，下半区域按工作流切换，只有浏览显示目录。
- 筛选只在一个位置编辑，主区以摘要反馈，不重复维护另一份条件状态。
- 人物明确全局与本库组；收藏仍按本库；标签计数仅统计图片。
- 工具独立滚动，底部入口保持可达；手机入口随功能命名，有关闭按钮与 Escape。
- 上方导航略收紧，为下方工具留出更多空间；当前选择和计数都有文字与语义状态。

## 实际执行

- 四种侧栏在390/768/1440/1920px共16组检查：无横向溢出，上下文工具存在。
- 手机每页打开/关闭抽屉，控件操作后继续可达。
- 搜索切当前目录、画面语义，输入“森林”，显示4项；范围摘要同步。
- 人物切未命名组显示当前库选择器；切已建立人物显示全局范围，查找白露为1项，点入详情。
- 收藏视频筛选为1项，预览选择同步至.mp4；取消后结果为空、旧预览消失；切回全部为3项。
- 标签用英文别名查找森林，改英文显示后仍为Forest和4张图片，标识不变。
- 切换不同功能后各自筛选状态保留。浏览目录树与管理中心导航仍可用。
- 浏览器控制台error为0。测试定位中曾遇到“搜索”重名按钮与包含option文字的label，
  已使用精确区域定位并为选择器补充明确aria-label；没有删除实质交互检查。
- `npm run build`与`npm run test:sites`（4项）通过，`git diff --check`通过。
