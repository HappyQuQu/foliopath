# ADR-0002：以单一允许根目录管理多个媒体库

## 状态

已接受（2026-07-23）

## 背景

FolioPath 需要像 Immich 一样允许用户在设置界面中新建多个媒体库，并为每个媒体库选择已映射到容器中的目录及其子目录。用户不应为每个媒体库修改应用配置或重建容器；Docker 只负责声明容器能够访问的最大文件系统边界。

同时，服务必须防止路径遍历、符号链接逃逸、媒体库重叠导致的重复索引，以及挂载暂时不可用时误删全部索引。原始媒体以只读方式挂载，删除应用内媒体库也不能影响原文件。

## 决策

- `/library` 是容器内唯一允许配置媒体库的根目录；`/app/data` 只用于应用配置、数据库和派生缓存，不能被选作媒体库。
- 推荐的最小 Docker 挂载为：

  ```yaml
  volumes:
    - /mnt/photos:/library:ro
    - ./data:/app/data
  ```

  多个互不相邻的主机目录可以分别挂载到 `/library` 的不同子目录，之后仍在设置界面中创建媒体库。
- 设置界面的目录选择器只能浏览 `/library` 内的目录。创建媒体库时配置名称和根目录，默认递归包含其全部子目录。
- 数据库保存相对于 `/library` 的规范化媒体库根路径。目录和媒体记录保存 `library_id` 与相对于该媒体库根目录的路径；不保存或暴露主机绝对路径。
- 媒体的逻辑身份是 `library_id + relative_path`。公开 API 使用媒体库 ID、目录 ID 或媒体 ID，不接受客户端提供任意绝对路径作为文件读取参数。
- 只有文件系统边界包可以把媒体库根路径和相对路径解析为实际容器路径。解析必须进行组件级边界检查，并在跟随符号链接后再次验证真实路径仍位于对应媒体库根目录和 `/library` 内；拒绝 `..`、绝对路径、编码绕过和符号链接逃逸。
- 创建或修改媒体库前，解析并校验其真实根目录。默认拒绝相同、祖先或后代关系的媒体库根目录，避免同一文件被多个媒体库重复索引。
- 媒体库根目录不存在、无法读取或挂载暂时丢失时，将媒体库标记为离线并保留已有索引。恢复可访问后再重新扫描。
- 删除媒体库只删除其配置、索引、任务记录和派生缓存；绝不移动、重命名、修改或删除原始媒体及目录。

## 后果

- Docker 配置只定义允许访问的上界，用户可以在不重建容器的情况下通过界面管理 `/library` 下的多个媒体库。
- 容器无法访问未挂载的主机目录；新增一个超出当前挂载边界的主机路径仍需要先修改 Docker volume，这是预期的安全边界。
- 相对路径模型避免泄露主机路径，并使数据库在保持相同容器挂载布局时可以迁移。
- 默认拒绝重叠根目录可避免重复索引、重复搜索结果和缓存归属歧义，但用户不能有意把同一文件同时放入两个媒体库。
- 指向媒体库外部的符号链接不会被浏览，这是为保证只读范围和路径隔离而接受的限制。
- 媒体库目录移动或根路径变更可能需要重新索引；应用不承诺根据 inode 或内容哈希自动识别跨路径移动。
