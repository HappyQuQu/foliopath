# ADR-0042 媒体删除与回收站

> 当前执行决策以 [ADR-0044](0044-simple-media-deletion.md) 为准：撤掉 Landlock/隔离子进程，不改 PVE；222/9090 本次获准候选升级并启用删除和回收站。下文 S1～S3 验收状态为此前记录，通用 S4 发行门禁仍保留。删除时外部程序不能移动同一目录或其父目录。

- 状态：Accepted（能力方向及只读约束的有限调整），2026-10-30。用户明确要求支持删除，并调整架构约束、产品合同和挂载权限；具体交互与实施方案见下列合同。S1/S2 本地门禁已通过，S3 已接入生产组件；未部署到真实媒体。
- 范围：POST-MVP / DELETE-S0～S4；CR-2026-058；FR-DEL-001～010、NFR-DEL-001～004。
- Owner：`internal/deletion` 拥有删除、回收、恢复及保留策略；`internal/files` 独占媒体文件系统写边界；SQLite adapter 拥有持久操作日志、隔离及分批事务；`internal/app` 组合既有 jobs/resourcecontrol。
- 设计合同：[媒体删除与回收站方案](../architecture/media-deletion-contract.md)。S1 通过前，本文及方案不代表可调用的 HTTP API。

## 背景

浏览媒体时需要删除不再保留的图片或整套文件夹。转到其他工具定位原目录增加操作成本，逐文件 HTTP 删除和删除前完整统计又使大目录操作长时间阻塞。既有“所有应用路径永远只读”同时约束 PRD、files、部署与测试，无法只增加一个按钮或回收站开关解决。

## 决策

将绝对只读约束调整为默认只读、显式授权的有限媒体变更。扫描、浏览、分析、缓存及媒体库配置移除仍不改变原件；只有本 ADR 的删除、回收和恢复用例可改动媒体目录项，不改写媒体内容，不扩展为上传、编辑或任意移动/重命名工具。历史 MVP scope 不重写，此能力独立按 POST-MVP 交付。

保留单一 `/library` 媒体挂载和既有 `/app/data`。基础 Compose 继续 `read_only: true` 挂载媒体。未来增加显式写入覆盖配置，仅将同一 `/library` 改为可写；容器根文件系统仍只读，AI 无媒体/data 挂载，所有已有 AI/data overlays 保留。Web 中另需管理员开启“允许删除原文件”，默认关闭。可写挂载不等于应用授权，回收站关闭不等于关闭删除。

回收站默认开启，默认手动清空；可显式设置 7/30/90 天自动清理。开启时整文件/整目录移动到 `/library/.foliopath-trash/<instance-id>/<entry-id>/payload`，该保留区是普通目录，不是新挂载。关闭时在原位置直接执行后台递归删除，不悄悄改成隐形回收站。两种方式均持久批量入队，不让浏览器递归枚举文件或等待整个目录删除结束。

恢复不覆盖、不合并同名目标；回收站关闭不会清空已有内容。暂停/取消只能阻止尚未执行的工作，永久删除已经完成的部分无法撤销。回收站未清理前保留资产身份和人工整理状态；永久删除及清空后分批清除对应资产关系，人物名称和全局标签定义不被误删。

所有写操作由 files 通过锚定的 Linux 目录描述符完成；保留路径、符号链接及禁止跨挂载约束。`openat2` 的打开保证不能自动推导为后续 rename/unlink 的写入保证，S1 必须有独立的写边界验证。普通源读取继续只读，不能让其他能力获得通用文件写入入口。不提供浏览器任意路径、命令执行、云盘原生 API 或跨文件系统复制回退。

扫描、所有读取投影及在途派生提交共同遵守删除隔离；SQLite 与文件系统之间使用先记意图、执行、再确认的恢复协议，不宣称两者有一个原子事务。复用现有进程内 WorkerPool、资源控制、认证/CSRF、游标、错误和生成客户端；不增加部署单元。

## 替代方案

- 继续依赖外部删除：保持最小权限，但不能完成浏览中的整理操作。
- 页面逐文件调用删除：请求数、网络往返和刷新成本随文件数增长，不能作为大目录主路径。
- HTTP handler 内执行递归删除：浏览器超时和断线使完成状态不明确，不能保证重启续作。
- 统一隐式移动后清理：能快速移走目录，但违背用户关闭回收站后的永久删除语义。
- 单独的特权删除服务：增加部署和信任边界，不符合当前规模与拓扑。

## 后果与准入

启用写入后，主容器失陷可能修改可写媒体树；UI 开关不能恢复只读挂载提供的隔离强度。默认只读模式继续受支持，关闭应用删除权限只约束应用用例；需要操作系统级只读时必须停任务并恢复只读挂载。

回收站占用原媒体存储，不属于缩略图配额，也不承诺释放磁盘空间。真实永久删除仍受文件数量和存储性能限制。首版只支持通过原生 Linux 写边界验证的普通本地文件系统；SMB/NFS/FUSE/CD2/云盘及 Docker Desktop 媒体写入不自动获得支持，继续可只读浏览。

DELETE-S1 必须固定写边界、OpenAPI/数据合同、故障恢复和扫描/AI 隔离证据，DELETE-S2 Backend Ready 后才可实现正式 UI。原生双架构、旧只读模式回归、容量与正式发布/实例迁移在 S4 单独验收。合同、后端、生成客户端、生产 UI 和本地验证已实现；基础 Compose 仍只读，真实媒体和现有实例不变。新增 compose.media-mutations.yaml 仅为待 S4 准入的显式覆盖候选，不代表已授权真实启用。
