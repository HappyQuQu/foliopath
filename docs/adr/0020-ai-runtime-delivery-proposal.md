# ADR-0020：FolioPath 专用 AI 镜像（方向已接受，实现中）

日期：2026-09-15。范围：POST-MVP-5 / CR-2026-030，续 ADR-0019。
Owner：app 部署组合、inference 服务、aimodel 身份准入。

## 需要决定的问题

用户已接受两个独立容器、Compose 配置模型、本地 Docker 测试；ADR-0019 则明确把
原版 Immich 镜像限定为协议探针，尚未选定正式推理镜像交付方式。
真实推理、回填和数据库重开检索已通过，但这些测试没有解决部署身份绑定。

核对固定 v3.1.0 的上游 main.py：`/ping` 只返回 pong，`/predict` 返回推理输出和图片尺寸，
没有模型文件摘要或 FolioPath 的向量空间身份合同。仅将其 URL 接入或填写若干摘要不能
证明 HTTP 实例对应哪个缓存。不得把本地缓存基线或成功推理伪称身份认证。

来源：
[上游固定版本 main.py](https://github.com/immich-app/immich/blob/v3.1.0/machine-learning/immich_ml/main.py)。

## 已接受方案 A：FolioPath 专用 AI 镜像

用户于 2026-09-15 回复“1”，接受方案 A。允许实现专用薄适配镜像；不等于镜像已通过发行 Gate。

保留主应用 + AI 两个容器。AI 镜像复用固定上游运行时与已有缓存，加入 FolioPath
版本化协议、启动时缓存校验、受支持模型限制和身份响应。Compose 仍由部署方固定镜像
与只读缓存，主应用不挂 Docker socket、模型或 AI 数据目录。

身份响应只能在受信部署边界内作为兼容性证据，不声称抵抗恶意部署方或构成远程 attestation。
须先定义协议、缓存读取/变更失败语义、摘要来源及主应用准入；涉及信任边界与新镜像
维护责任，故先提出交付决策，不直接写生产实现。上游许可证、依赖和双架构验证仍需完成。

优点：接口与缓存验证由项目拥有，主应用可明确显示不兼容/不可用。
代价：项目维护第二镜像的薄适配层与升级验证；不再是直接运行原版镜像。

## 方案 B：保持原版 Immich AI 镜像

不修改推理服务；部署工具在容器外核对固定镜像、网络与缓存，把信任交给受控部署流程。
需另行定义不可漂移的部署凭据、故障/重启验证；不能把现有 ping 当成身份接口。
优点：不维护上游派生服务；代价：部署工具成为准入的一部分，手工 Compose 的支持边界更严格。
