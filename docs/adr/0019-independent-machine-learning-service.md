# ADR-0019：独立机器学习服务与部署驱动模型配置

- 日期：2026-09-14；状态：Accepted direction / implementation in progress。
- 授权：用户确认参考 Immich 的主应用 + 独立 AI 服务，并复制 server222 已下载模型用于本地测试。
- 范围：POST-MVP-5 架构修订 / FR-INT-017/019/020、NFR-INT-007/009/010。
- Owner：app 部署组合、inference 服务适配、aimodel 模型配置、semantic/face 代次、SQLite 持久化。

## 决策

AI 部署采用主应用 + 可选独立机器学习容器；替代 ADR-0013 的 AI 单进程/单容器限制。
主应用保留 Go、SQLite、认证、媒体访问、任务准入与状态；AI 服务负责模型缓存与推理。
不引入 Redis/PostgreSQL，不把扫描、索引或任务所有权搬进 AI 服务。
Compose 管理服务地址、固定镜像版本、受支持模型标识、缓存与代理配置；不以模型商店为产品入口。
界面保留能力开关、实际状态、错误与分析进度。旧下载 API/持久状态迁移须先接受合同再改动，
不能删除旧迁移或将旧 embedding 当成新模型输出使用。

## 信任边界与协议要求

默认同一 Docker 私有网络，AI 端口不发布到 LAN；不挂载原媒体或主应用数据库。
主应用只通过 internal/files 获取受控图片载荷；图片/文本在本机容器间传输，不上传云服务。
跨机器 AI 暂不授权默认开启，须另行定义认证/传输保护。地址只能由部署配置，不接受浏览器 URL。
服务超时、不可用、维度/模型身份不符必须失败关闭并保留可靠索引；有界并发/载荷/响应。
模型从固定受信来源下载、逐文件 hash 校验与原子缓存；失败不切换未知来源。
ADR-0016 的商店式配置被新方向替代，但供应链约束不因拆容器消失；HF 发布仍暂停。

## 先验证再迁移

第一步使用固定版本 Immich ML 镜像作隔离协议/模型探针，不直接作为已批准的生产依赖。
复制 server222 的缓存到本地独立目录，核对前后 hash，仅合成图片与非敏感文本测试。
上游镜像的许可、依赖闭包、缓存安全及协议兼容需验证；不可把“可启动”当成生产接入。
现有 SigLIP 768 维合同不能直接接收 CLIP ViT-B-32 的向量；模型身份、维度、预处理和新代次
合同必须一同演进。buffalo_l 同样不能冒用现有 YuNet/AuraFace 合同。
第二步定义内部协议及故障语义，集成测试主应用 adapter，再迁移 UI/Compose 默认交付。

## 备选与影响

不继续要求用户上传项目转换包；优先适配已有上游模型。暂不承诺原样复用 Immich 镜像为最终方案。
代价是新增 HTTP 边界、资源预算和第二镜像验证；收益是隔离 native 依赖并复用模型缓存。
MVP 默认部署与历史 Gate 不变；新 AI 架构必须补齐 backend、双架构、质量和发行证据。
