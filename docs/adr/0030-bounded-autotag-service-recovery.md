# ADR-0030：自动标签服务短暂不可用的有界恢复

- 日期：2026-10-24；状态：Accepted（用户要求修复model_unavailable并保留进度补齐8k/pixiv）。
- 范围：POST-MVP-5 / CR-2026-031、FR-AUTOTAG-001/002、NFR-OPS-001；Owner autotag/remoteml/app。
- 不改变模型身份、部署单元、公开API、数据库或原三次异常claim恢复上限。
- 实施/验收：定向/race、全量Go、集成/runtime E2E及真实模型Docker故障回归通过，备份后更新6010；8k/pixiv仅missing补齐已终态，21:08核验无新增任务级model_unavailable，四库8690成功/10既有源失败/未处理0、人工保护摘要一致。详细证据见[修复记录](../changes/FIX-2026-10-24-autotag-service-recovery.md)，非发行通过。

## 背景

6010在两个服务停止再启动后，8k和pixiv原operation以model_unavailable终止并阻止自动重入。
已提交的结果保留，但队列领取早于AI完成启动时，一次短暂断连也会终止整库任务。
既有错误没有保存底层原因，不能宣称历史失败的精确网络/推理原因已被证明。

## 决策

1. remoteml只把tag传输断连、身份端点503及携带完整正确身份和严格unavailable响应的预测503标记为临时不可用。
   不匹配身份、非法输出、重定向/其他状态仍为原硬失败；不降级模型，不绕过逐次身份核验。
2. app只映射该明确类型到autotag临时不可用。autotag拥有唯一恢复策略：每张图片最多60秒总窗口，
   最多额外2次实际分析；每秒探测身份，短暂不可用/忙时等待，身份恢复后才再送图片。
   窗口包含探测、忙重试、实际分析；上下文取消立即退出，等待不持有SQLite事务，现有heartbeat维护租约。
3. 等待期间不提交空标签/失败图片、不推进checkpoint、不替换operation或撤销claim计数。
   到期、额外分析次数耗尽或硬失败仍终止model_unavailable并保留人工介入要求；不无限重试或复活历史终态任务。
4. 已失败的6010两库，仅在验证通过后通过既有带修订保护的启用设置解除阻止，使用既有missing调度各创建一次补齐任务。
   原终态operation保留；已有当前身份run（包括已知源失败）不会再处理，不清空人工标签/删除抑制/旧向量。
   未遇到的两张空源仍可记录failed，不伪造成功。无需新任意图片排除API或直接修改任务/claim表。

## 验收

覆盖短暂不可用恢复、永久不可用有界停止、取消、身份不符与非法输出不重试、既有busy行为；
合成Docker中AI延迟启动/单独停止再启动时同operation继续，checkpoint与人工/删除抑制保留、原件hash不变。
再更新6010主镜像，保留模型身份、三Compose和只读挂载；仅补齐8k/pixiv，不把部分终态计数当全库成功。
