# ADR-0039：固定 AI profile 与自动模型准备

- 状态：已接受实现；2026-10-27 用户明确要求在独立分支实现简化 AI 部署。公开发布仍须双原生同 digest 验证。
- 范围：CR-2026-053；POST-MVP-5 / P6；FR-INT-017/019/020，NFR-INT-007/009/010。Owner：部署 / internal/app / inference runtime。

## 背景

旧双服务部署要求管理员准备只读模型缓存、手工提供 deployment JSON。旧清单还记录下载器的本机时间戳，不能由公开固定源重现。用户要求只修改目录和端口即可启动两个容器，不运行生成程序、不填写模型摘要。

## 决策

新增显式 `standard-v1` profile，与旧离线 Compose 并存。主镜像内嵌由 canonical runtime 生成的预期身份和参数，不从在线 AI 服务首次信任身份。AI 镜像内置固定源、版本、大小和 SHA256 清单，首次启动自动下载，验证后原子发布；复用已验证缓存，失败自动重试，停机取消下载。只有 AI 获得外网及专用模型缓存写权限；主应用继续只有媒体只读和 data，不挂模型目录或 Docker socket。仍为两个部署单元，推理调度器和有界子进程不变。

新 profile 的 legacy manifest 只包含两个 buffalo_l 权重，去掉下载器元数据和未使用的旧英文 CLIP；多语言语义、JoyTag、OCR 字节和预处理合同不变。清单变化产生独立 face identity，不能重标旧结果。旧离线 profile 及 frozen runtime 源码不修改。人物默认阈值是明确版本化的工程默认，不冒充质量标注结论。

部署入口使用普通 bind 短格式；模型和验证 scratch 都在专用 models 目录内，两个子目录映射到既有 runtime 路径，不接触原件或数据库。准备中普通图库继续启动，库的 AI 开关仍由管理员显式启用。下载固定模型，不接受用户 URL、任意模型名或服务端推荐身份；保留 TLS、摘要和大小校验。只使用显式下载代理，不继承 ambient proxy，无隐式直连降级。

## 替代方案

- 把全部权重打进镜像：显著增加镜像与每次更新传输，暂不采用。
- 从 AI identity HTTP 响应生成配置：失去独立预期身份，不采用。
- 新增安装容器：增加部署和故障点，不采用。

## 后果及验收

需维护固定源目录、profile 生成检查、下载失败/取消/损坏恢复测试及匹配的双架构 AI 标签发布。模型许可说明保留，自动获取不代表商业许可或质量认证。旧实例继续显式配置，不默认迁移、不自动开启库或清除结果。公开源可用性与完整真实模型启动、各功能推理须独立记录；未执行的验证不能声明通过。
