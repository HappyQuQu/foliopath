# ADR-0041：只读 7z 图片来源

- 状态：Accepted，2026-10-29 用户明确要求“支持7z”。
- 范围：CR-2026-056；POST-MVP / ARCHIVE-S2；FR-7Z-001～003、NFR-7Z-001。Owner：files / scanner / media / browse。

## 决策

沿用 ADR-0040 的虚拟目录、显式成员来源、稳定资产身份、失败保留、Range、缩略图和 AI 排除合同。`v1:z` 继续表示已有归档成员来源族，路径和包版本仍参与指纹；不改变已有 ZIP 指纹或数据库结构。公开 archive 字段覆盖 ZIP 和 7z，字段和状态枚举不变。

files 通过锚定文件描述符读取单卷、未加密 7z。使用 Debian 7zip 的原生解析器，按请求启动受限子进程；仅通过继承的 `/proc/self/fd/3` 接触已打开原包，不将成员名用作磁盘输出路径。`prlimit` 在启动解码器前限制地址空间 256 MiB、CPU 60 秒；上下文取消、60 秒墙钟和最多两个子进程约束扫描与读取。清单输出不超过 8 MiB，实际图片输出不超过 64 MiB，校验大小与 CRC 后才公开临时流。原包只读，临时文件和缩略图继续归既有 owner。

首版支持 7zip 可读取的图片成员，包含固实与非固实包；沿用 10,000 条目（含补齐目录）、累计声明展开 4 GiB、路径 32 层和单图 64 MiB。密码包、分卷、自解压、嵌套包、视频和 AI 不纳入。固实包读取可能重复解码同块前缀，受同一截止时间与内存限制；本片不增加持久原图缓存或后台全包展开，不承诺 50 GB 包或固定浏览延迟。

## 原因与后果

Go 7z 候选解析器在读取文件数量与字典等字段后、应用能校验之前分配内存。复用现有原生工具适配方式，将解析/解码放在硬资源限制内，避免把此分配带入主进程；不增加部署单元。正式镜像需要随包携带 7zip 与 prlimit 及其许可证/依赖，两种原生架构均需验证。开发环境无工具时保留已收录内容并报告无法读取，不假装成功。

固实包的随机读取成本需要合成样本实测；若后续增加跨请求原图/块缓存，需要单独接受生命周期、配额与失效合同。超限和坏包继续保留旧索引，修复后重新扫描。
