# ADR-0029：独立版本化的自动标签 PNG 输入

- 日期：2026-10-24；状态：Accepted（用户授权先备份、合成 Docker 通过后更新6010）；实现/验收另记，不代表发行。
- 范围：POST-MVP-5 / CR-2026-031、CR-2026-033 / FR-AUTOTAG-001～003；Owner app/imagevips/autotag/curation。
- 前置：[ADR-0028](0028-versioned-png-semantic-input.md)仅修复语义输入，旧标签32项失败中22项仍命中v3 PNG限制。
- 实施状态：Go/race/native及真实模型合成Docker通过；22张PNG逐图新身份ready/源指纹一致（21张有AI标签、1张0候选）。经ADR-0030修复服务暂时不可用并missing续补，21:08四库终态核验8690成功/10既有源失败/未处理0，保护摘要一致。10项源问题仍暂不修复，不代表质量/发行通过。

## 决策

1. 部署JSON `tag.image_preprocessing` 独立选取空值（原v3）或`png-v4`；严格拒绝其他值。
   不继承顶层语义profile，不更换JoyTag权重、92类策略、阈值或AI镜像，不借此启用153类。
2. app用该profile的canonical contract同时构造标签fingerprint和imagevips预处理器；空值必须与旧标签身份逐字相同。
   png-v4创建新的独立标签身份，不改语义/人脸代次、不伪装为仅补旧失败。
3. 复用ADR-0028/0024的64 MiB、40 MP、1 MiB头预算、唯一native准入及统一输出，不复制解码/内存/transform实现。
4. 保持既有按库启用、有界全局队列、fenced原子标签合并和checkpoint、人工优先及持久删除抑制。
   切换后已启用库按新身份由既有missing调度重新识别；旧标签不会被预先清空，旧成功不计新覆盖。
   `autotag_asset_runs`仍为每资产最新尝试记录，更新会替换该行；历史operation及切换前完整备份保留回退依据，不新建历史表。
5. 用户要求跳过的10项源错误不改写、不修复、不伪造成功；新身份全库遍历中可能再次记录源输入失败，
   失败不自动循环重试。没有新加入任意资产排除API或把已知坏源自动标ready。
6. 先停写完整备份并验证，恢复原版服务；合成Docker通过后再停写核对当前数据是否仍与备份相配，
   不匹配则重新完整备份。仅更新主镜像与tag profile，保留三份Compose及原AI身份/挂载/不限内存选择。

## 替代方案与验收

- 直接放宽旧tag常量或继承语义profile会静默改变旧身份，拒绝；全量清除AI/人工标签、改原件也拒绝。
- 不扩展自动重试策略或失败明细API；旧记录未保存逐图解码码时不得补造历史原因。
- 必须验证默认身份不变、非法配置失败、tag/语义/人脸独立，真实大PNG从旧失败转新成功，
  损坏/空源保留失败，人工标签/中文同义优先、删除抑制跨换代及重启仍有效，原件hash不变。
- 当前质量、默认预算、长期、大容量、跨架构和完整发行门禁不由功能烟测关闭。
