# ADR-0004：MVP 媒体库根路径创建后不可变

## 状态

已接受（2026-07-23）

## 背景

[ADR-0002](0002-library-path-model.md) 已决定媒体库由 `/library` 下的安全相对根路径定义，并以 `library_id + relative_path` 标识媒体。产品确认进一步要求：媒体库名称必须在实例内唯一并可改名，但 MVP 不提供原地修改根路径；更换目录通过从 FolioPath 移除旧媒体库后重新创建完成。

原地修改根路径不仅是配置字段更新。它需要决定旧目录/媒体 ID 是否保留、扫描和缩略图任务如何失效、旧缓存何时清理、失败时回到哪个根目录，以及新旧路径暂时离线或重叠时如何恢复。首版没有足够用户价值支持这组迁移状态。

## 决策

- `libraries.name` 非空且在实例内唯一；允许通过普通更新操作改名。
- `libraries.root_rel_path` 创建后不可变。MVP 的更新 API 不接受该字段，服务层也不提供修改根路径的方法。
- 用户需要更换根路径时，先执行“从 FolioPath 移除”，再选择新路径创建新的媒体库。
- 移除仍只删除配置、索引、任务和派生缓存，不修改原始目录或媒体。
- 重新创建得到新的媒体库 ID、目录 ID、媒体 ID、扫描历史和派生任务；不承诺把旧索引、URL、缓存或浏览位置迁移到新媒体库。
- UI 必须在媒体库设置中把根路径显示为只读，并在移除确认中解释原文件不受影响。
- 未来若需要原地迁移根路径，必须新增替代 ADR，定义状态机、ID/缓存迁移、重叠校验、失败回滚和 API 兼容性。

## 后果

- 数据模型、API 和任务恢复不需要支持同时存在的新旧根路径或部分迁移状态，首版实现与故障恢复更简单。
- 改名不影响媒体库 ID、相对路径、索引、缓存或 URL。
- 更换根目录需要完整重扫和重建缩略图，可能耗时且会产生新的资源 URL；界面应在操作前说明。
- 用户无法通过修改根路径快速修复挂载布局变化。推荐先恢复相同容器内 `/library` 布局；确需更换时移除后重建。
