# ADR-0040：只读 ZIP 图片来源

- 状态：Accepted。2026-10-29 用户先授权独立分支试用，验看后明确要求更新 README、提交、推送、合并及发布；发行结果以原生双架构门禁记录为准。
- 范围：CR-2026-055；POST-MVP / ZIP-S1；FR-ZIP-001～004、NFR-ZIP-001。Owner：media / files / scanner / catalog / SQLite / app。

## 背景

现有资产直接对应库内普通文件。用户希望不手动解压即可浏览 ZIP 图片，保留原件及包内层级。包内成员不能作为真实文件路径交给内核文件边界。

## 决策

ZIP 是文件系统中只读的来源容器，在派生目录索引中呈现为可进入的虚拟目录。包和成员身份分开持久化；成员继续使用现有资产 ID、目录计数、游标、缩略图和查看器。库根仍只能选择真实目录，单一 `/library` 挂载和内核边界不变。

media 拥有 ArchiveMember 与 `v1:z` 源指纹；files 拥有已打开 ZIP 的有界解析及单成员展开。scanner 传递显式来源，SQLite 在原批次事务中更新成员、来源及缩略图任务。app 只负责组合。普通文件 v1 指纹及原有能力保持兼容。

首版支持未加密、单卷、非 ZIP64 的 Store/Deflate ZIP，UTF-8 名称，JPEG/PNG/WebP/GIF，保留子目录。视频和嵌套包不展开，RAR/7z/密码包不支持。上限为 10,000 个条目、8 MiB 中央目录、单成员 64 MiB、累计声明展开大小 4 GiB、32 层目录。解析入口拒绝不安全路径、重复成员和特殊文件；读取时另以实际输出字节数约束解压，不相信声明大小。

原件经 files 的锚定打开读取。成员按请求展开至 `/app/data/tmp/zip` 的随机临时文件，最多两个活跃展开/读取、每个 64 MiB，关闭删除，启动清理遗留临时内容；缩略图继续使用现有持久缓存配额。源版本绑定包大小/修改时间与成员 CRC/大小/修改时间，打开时核对来源，变更使旧派生结果失效。临时文件不是媒体真相，不增加部署单元。

失败包保留旧成员和人工整理数据，标注无法读取；只有成功全扫描确认包不再存在或成功读取新清单时才清理陈旧成员。扫描取消/失败继续遵守现有保留原则。目录快速校准遇到 ZIP 转为全扫描，不把虚拟目录注册为真实 watcher。

ZIP 图片可沿用现有资产的字面搜索、收藏及人工标签，不新增独立整理流程。首版不准入语义、人物、自动标签或 OCR 任务，其候选与覆盖统计必须排除 ZIP 来源；后续启用需单独验证。

## 替代方案与后果

整包永久解压会占用重复空间并引入第二份媒体树；仅在查看器临时解析又无法复用目录分页和稳定资产身份。采用显式成员来源需要一次新增迁移、目录 API 的加法字段和来源回归。重新打包保留相同逻辑路径的资产与人工整理；重命名不猜测迁移。已有数据需按原备份流程升级，本分支使用合成独立数据验证。

验证必须包含真实 ZIP 扫描、内容/Range、缩略图、改包失效、损坏保留、取消、路径拒绝、AI 排除，以及四档宽度的生产界面。macOS 测试不替代 Linux 文件边界；正式发布仍需原生双架构门禁。
