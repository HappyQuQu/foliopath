# ADR-0007：采用单一共享前端设计系统与组件所有权

## 状态

已接受（2026-07-23）

## 决策角色

- 产品：相同操作、状态和列表必须形成一致体验
- 架构：前端分层、依赖、单一所有权与质量门禁评审
- 可访问性：基础交互不得由 feature 分别实现焦点和键盘语义

## 背景

FolioPath 的设置、扫描、目录、搜索和查看器会反复使用按钮、字段、对话框、状态反馈和大型集合。
若每个 feature 自行实现这些语义，相同操作会产生不同样式、键盘行为、错误状态和维护方式。
仅在视觉规范中列出颜色或组件名称，无法阻止源码中出现多套实现。

## 备选方案

1. **完全 feature-local。** 起步简单，但基础控件、Query、列表与样式会快速分叉。
2. **直接采用一套完整第三方视觉组件库。** 可减少初始代码，但可能与内容优先视觉、虚拟列表、
   体积和可访问性要求不匹配，仍无法解决业务状态/API 所有权。
3. **内部单一设计系统，必要时在其内部包装一套无样式基础原语。** 使用集中 token、受控 variant、
   组件工作台和所有权 lint；业务组合仍留在 feature，避免万能组件。

选择方案 3。若以后选择无样式基础库，只能有一套并由共享 UI 层封装；更换需要新的 ADR。

## 决策

- `web/src/components/ui` 拥有跨 feature 的 UI 原语，`web/src/components/patterns` 拥有跨 feature
  的交互模式；每个语义角色只有一个规范实现和一组受控 variant。
- feature 只拥有其业务组合与业务专用组件。发现第二个消费者或基础语义时，将实现提升到共享所有者，
  而不是复制文件；不得建立第二套 Button、Field、Dialog、Sheet、Banner、Toast、异步状态或集合控制器。
- 样式使用集中 CSS custom-property token 与组件级 CSS Modules。feature 不得使用原始颜色、另建间距／
  圆角／阴影／层级／动效体系，也不得创建第二个主题机制。
- 前端依赖方向固定为 `app/routes -> features -> shared components/lib/styles`。共享层不依赖 feature；
  feature 不导入另一 feature 的私有文件；HTTP 只经生成客户端边界和手写领域 adapter。
- Query key、URL codec、API error 映射、mutation invalidation 与请求取消策略各有唯一所有者，不按页面复制。
- 共享原语和稳定交互状态必须进入组件工作台；深浅主题、中英文本、桌面／移动、加载／空／错误／离线
  等稳定矩阵执行组件、无障碍与聚焦视觉回归。动态媒体内容不做大面积脆弱像素快照。
- 首个业务 feature 前，TypeScript strict、import-boundary/cycle lint、token lint、其实际消费原语的
  组件/axe 测试和组件工作台构建成为 CI 门禁。原语 API 稳定或出现第二个消费者前建立聚焦视觉基线；
  完整主题/语言/断点矩阵最迟在 Release Candidate 前阻断发布。

## 后果

- 相同语义获得一致行为、样式和无障碍实现，缺陷修复可以在单一所有者处完成。
- shared 与 feature 的边界需要持续评审；“可能复用”不能成为提前建立抽象的理由。
- 组件工作台和视觉矩阵增加维护成本，但其范围只覆盖稳定原语与关键状态，避免快照泛滥。

## 验证与复审

- 由前端 import boundary、token lint、组件工作台构建、组件／无障碍测试和视觉回归执行。
- 只有在证明某语义存在无法用 variant 表达的不同交互契约时才允许拆分，并须更新前端架构说明。
