# ADR-0003：使用扫描代次保证索引最终一致性

## 状态

已接受（2026-07-23）

## 背景

媒体库可能包含大量文件和深层目录。扫描期间可能发生进程退出、权限错误、文件写入、重命名、删除或挂载暂时离线。如果扫描器在尚未确认完整遍历成功时删除“未发现”的记录，一次中断或存储故障就可能把现有索引误判为空。

扫描还必须在低资源设备上运行，不能把完整目录树加载进内存，也不能为每个文件创建无限 goroutine。未来的文件系统 watcher 可以缩短变更可见时间，但不能作为正确性的唯一来源。

## 决策

- 索引采用最终一致模型。启动扫描、手动扫描和定时完整扫描构成正确性基线；文件系统 watcher 只能作为触发增量工作的优化。
- 每个媒体库的完整扫描使用单调递增的 generation，并在 `scan_runs` 中记录开始时间、状态、进度、错误和结束时间。同一媒体库同一时间最多运行一次扫描，重复请求合并或排队。
- 完整扫描按以下阶段执行：

  1. 验证媒体库根目录存在、可读且真实路径仍在允许边界内；验证失败时将媒体库标记为离线，不创建会触发清理的成功代次。
  2. 流式遍历目录。分批 upsert 目录和媒体记录，并把其 `last_seen_generation` 更新为当前 generation。
  3. 每批写入在有界事务中提交；提交完成后再创建或更新所需的派生媒体任务。
  4. 只有全部遍历和索引写入都成功后，才在事务中清理 `last_seen_generation` 早于当前 generation 的记录，并把扫描标记为成功。
  5. 扫描失败或取消时保留未见到的旧记录，将运行标记为失败或取消；已确认存在并成功写入的新记录可以保留。

- 任一无法可靠遍历的子目录、权限错误或 I/O 错误都使本次完整扫描不具备清理资格。错误必须记录并在媒体库状态中可见。
- 进程启动时把遗留的运行中扫描标记为中断。中断代次不得执行陈旧记录清理；之后通过新的完整扫描恢复一致性。
- 文件身份以 `library_id + relative_path` 为准。大小、精确修改时间和媒体类型等签名用于判断是否需要重新探测元数据或生成缩略图；重命名在成功完整扫描后表现为新增新路径并清理旧路径。
- 增量扫描只能更新已明确检查的路径，不执行媒体库级陈旧记录清理。定期完整扫描负责纠正漏掉的事件和目录级变化。
- 遍历、数据库批处理、图片缩略图和 FFmpeg 工作都使用有界队列。所有媒体库共享全局媒体处理并发上限；数据库写入串行化，单批事务保持有限规模。
- 缩略图与视频封面属于可重建数据。文件先写入同目录临时文件，再原子替换目标文件；超时、失败或签名变化时任务可安全重试。

## 后果

- 挂载丢失、权限错误和进程中断不会触发大规模误删索引，离线媒体库仍可保留已有目录与媒体信息。
- 扫描失败后，已从磁盘删除的文件可能暂时继续出现在索引中，直到下一次完整扫描成功；界面需要区分扫描状态，并能处理打开文件时文件已不存在的情况。
- 文件在扫描期间继续变化时无法获得严格快照；变化最迟由后续增量或完整扫描收敛，这是所选最终一致模型的预期行为。
- generation 清理比逐项即时删除更安全，但需要额外的扫描状态字段、成功提交阶段和失败恢复测试。
- 流式遍历和全局有界队列限制内存与 CPU 峰值，不过大型媒体库的首次完整扫描仍可能耗时较长。
- watcher 丢事件不会永久破坏索引正确性，但定期完整扫描会带来可控的额外 I/O。
