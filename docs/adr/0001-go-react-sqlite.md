# ADR-0001：采用 Go、React 与 SQLite 的模块化单体架构

## 状态

已接受（2026-07-23）；`cmd/foliopath` 与 `internal/app` 的组合根责任由 [ADR-0008](0008-composition-root-and-path-policy.md) 修正

## 背景

FolioPath 是面向 NAS、家庭服务器和个人设备的自托管媒体浏览器。核心工作负载包括递归扫描大型目录、维护派生索引、生成图片与视频缩略图，以及通过 HTTP 流式传输原始媒体。项目希望保持部署简单：一个容器、一个端口、一个持久化数据目录，不要求用户额外部署数据库、缓存或独立任务服务。

前端需要支持目录树、递归媒体列表、游标分页和虚拟化布局；后端需要低资源常驻、可控的并发和清晰的文件系统安全边界。媒体文件始终是事实来源，数据库只保存可重建的索引与应用配置。

## 决策

- 采用模块化 Go 单体作为后端和运行时入口。`cmd/foliopath` 只负责最小进程入口并把控制交给唯一组合根 `internal/app`；依赖组装、启动与优雅退出由 `internal/app` 统一管理，业务能力放在 `internal/` 下按领域划分。具体责任以 ADR-0008 为准。
- 使用 Go 标准库 `net/http` 提供版本化 REST API（`/api/v1`）和原始媒体的条件请求、Range 请求支持。
- 使用 React、TypeScript 和 Vite 构建单页应用。服务端状态由 TanStack Query 管理，长列表与瀑布流由 TanStack Virtual 虚拟化，可导航状态写入 URL。
- 前端产物嵌入 Go 可执行文件并由同一 HTTP 服务提供，不引入 Nginx、服务端渲染或独立前端容器。
- 使用 SQLite 保存媒体库配置、目录与媒体索引、扫描状态和任务状态。启用 WAL；写入串行化并采用有界批量事务。文件名和路径搜索使用 FTS5。
- SQL 访问使用 `sqlc` 生成类型安全代码，迁移使用 Goose 并嵌入可执行文件。已发布的迁移只允许追加，不允许修改。
- 图片探测与缩略图处理使用 libvips（通过 govips）；视频元数据和封面提取使用 `ffprobe` 与 `ffmpeg` 子进程。MVP 直接传输浏览器兼容的视频，不提供自动转码。
- 对外只运行一个应用进程和一个 HTTP 端口。媒体挂载在 `/library`，数据库、配置和派生缓存保存在 `/app/data`；SQLite 文件应位于容器本地或主机本地文件系统，不依赖 SMB/NFS 上的 WAL 行为。
- API 以 OpenAPI 文档为契约。生成的 SQL 与 API 客户端代码不得手工修改。
- 未经新的 ADR，不引入 PostgreSQL、Redis、GraphQL、WebSocket、独立 worker 服务或分布式任务系统。

## 后果

- 用户只需部署一个容器并持久化一个数据目录，安装、升级、备份和故障排查都较简单。
- Go 进程可以统一管理 HTTP 服务、扫描任务和媒体处理的生命周期及全局并发限制，但应用必须避免让后台任务阻塞请求处理。
- SQLite 很适合单实例、读多写少的派生索引；代价是当前架构不支持多个 FolioPath 实例同时写入同一数据库，也不面向水平扩展。
- 前后端仍使用两种语言和两套构建工具，但运行时只保留一个服务，且 API 契约可以降低两端漂移。
- libvips 与 FFmpeg 提供成熟的媒体能力，同时增加了镜像体积、跨架构构建和系统依赖维护成本。
- 不做视频转码可显著控制首版复杂度和资源消耗，但浏览器不兼容的编码只能显示元数据或封面，无法保证直接播放。
