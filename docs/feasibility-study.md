# FolioPath 可行性研究

## 结论与状态

FolioPath 在既定范围内具备实现可行性，但当前结论是 **有条件推进（Conditional Go）**：可以进入脚手架和验证性 spike，尚不应把未经验证的性能、媒体格式或跨架构能力承诺给用户。

本文依据已接受的 [ADR-0001](adr/0001-go-react-sqlite.md)、[ADR-0002](adr/0002-library-path-model.md) 和 [ADR-0003](adr/0003-scan-consistency.md)。产品规模、格式范围、认证边界等未决项以[需求确认清单](requirements-checklist.md)为准。

文中使用三种证据等级：

- **已知事实**：已接受的项目约束，或可直接从当前仓库确认的状态。
- **假设**：合理但尚未由用户需求、原型或测试证明的前提。
- **需 spike**：必须用小型可运行实验收集证据；本文不提供或虚构 benchmark 数字。

## 分项评估

| 维度 | 已知事实 | 假设与未知 | 需要的验证 | 初步判断 |
| --- | --- | --- | --- | --- |
| 产品 | 文件夹优先、多媒体库、递归浏览和只读原文件已经成为基线；Docker 只声明 `/library` 与 `/app/data` 边界 | 目标用户规模、首要浏览流程和相对现有工具的使用价值尚无真实用户证据 | 用可点击原型或最小纵向切片验证创建媒体库、定位目录、递归浏览和离线恢复 | 可行，但需先冻结 MVP 验收标准 |
| 技术架构 | 已决定采用 Go 模块化单体、嵌入 React SPA、SQLite、govips/libvips 与 FFmpeg；只运行一个服务实例 | 能力包边界和生成代码流程尚未由实际代码验证 | 建立最小服务，贯通迁移、API、后台任务、静态资源嵌入和优雅退出 | 技术组合成熟，集成风险可控 |
| 扫描与性能 | generation、流式遍历、有界队列和串行批量写入已有一致性设计 | 目标目录规模、存储介质、首次扫描时间、内存预算和交互延迟均待确认 | 在合成小/中/大目录树上测量扫描吞吐、数据库增长、查询延迟、队列积压和峰值内存 | 原理可行；容量结论尚无证据 |
| 媒体格式 | 图片计划由 libvips 处理，视频由 ffprobe/FFmpeg 探测和抽帧；MVP 不转码 | “常见格式”的精确定义、动画图片策略、浏览器可直放编码和损坏文件行为待确认 | 对拟支持矩阵逐项做探测、缩略图、方向、色彩、动画、海报和浏览器播放测试 | 可覆盖主流格式，但不能笼统承诺全部格式 |
| SQLite | 单实例、本地文件系统、读多写少且索引可重建，与 SQLite WAL 模型匹配 | 最大媒体量、FTS5 多语言搜索、长扫描写入与浏览并发的表现未知 | 真实 SQLite 迁移与故障注入；并行读取、批量写入、FTS、checkpoint、备份恢复测试 | MVP 可行；禁止把 `/app/data` 放在 SMB/NFS |
| 安全 | 已定义 `/library` 边界、只读挂载、相对路径、重叠拒绝和离线保留；媒体输入视为不可信 | 符号链接竞态、路径编码边界、解析器资源上限及认证上线范围尚未验证 | 路径逃逸测试、模糊输入、媒体炸弹/超时、无认证网络暴露和容器权限验证 | 设计方向正确；相关测试是发布阻断项 |
| 运维 | 目标为一个容器、一个端口、一个本地持久数据目录；缓存可重建 | 健康检查、磁盘配额、升级失败、数据库恢复和观测字段尚未实现 | 构建镜像并演练启动、停机、备份、恢复、迁移、磁盘满和挂载离线 | 部署简单，但恢复流程必须先演练 |
| 跨架构 | Go 支持 amd64/arm64；目标镜像包含原生 libvips 与 FFmpeg | govips 的 CGO、系统库、编解码能力和不同架构镜像内容可能不一致 | 在 linux/amd64 与 linux/arm64 构建并运行同一媒体 fixture 与容器冒烟测试 | 可行但不是“纯 Go”交叉编译，发布链路有明显风险 |
| 许可证 | 项目采用 AGPL-3.0-or-later，仓库已有许可证文本 | Go/npm 依赖、libvips、FFmpeg 构建选项、编解码库及分发地区的义务尚未形成清单 | 生成依赖与镜像 SBOM，核对许可证兼容性、源码提供义务及 FFmpeg 构建配置；必要时寻求法律意见 | 原则上可行，发布前必须完成合规审查 |

## 必做 spike

| Spike | 范围与产物 | 通过条件 |
| --- | --- | --- |
| FS-01 路径边界 | 仅实现安全目录枚举和文件打开，覆盖绝对路径、`..`、重复编码、符号链接、挂载消失与路径变化 | 所有逃逸样例失败关闭；合法子目录可用；错误不泄露真实路径 |
| FS-02 SQLite 与扫描 | 用合成目录完成迁移、generation 扫描、分批 upsert、中断恢复和成功代次清理 | 失败/中断/离线不清理旧索引；成功扫描可收敛；数据可重建 |
| FS-03 媒体矩阵 | 用许可清晰的小型 fixture 运行 govips、ffprobe 和 FFmpeg，记录每种候选格式结果与资源使用 | 形成明确支持/不支持矩阵；损坏文件和超时不阻塞队列或进程 |
| FS-04 容量基线 | 在需求清单确认的代表性硬件和数据规模上采集扫描、列表、搜索、缩略图和内存数据 | 结果可复现，并满足之后确认的目标；未确认目标前只报告测量值 |
| FS-05 镜像与恢复 | 为目标架构构建单容器镜像，验证非 root、只读媒体、健康检查、SQLite 备份/恢复与升级迁移 | 两个目标架构行为一致，恢复演练成功，镜像依赖和许可证可追溯 |

Spike 应提交可复现命令、fixture 说明、原始测量结果和结论。若硬件、数据集或构建选项不同，不得横向比较为同一 benchmark。

## Go / No-Go 门槛

### 允许进入 MVP 实施

- [需求确认清单](requirements-checklist.md)中的 MVP 阻断项已确定负责人并完成确认。
- FS-01 与 FS-02 通过，证明路径边界和 generation 清理不会破坏用户媒体或索引。
- FS-03 产出首版媒体支持矩阵，README 与实现使用同一口径。
- 性能目标、目标硬件和数据规模已经定义；FS-04 没有发现必须改写架构的阻断问题。
- FS-05 至少证明目标发布架构可构建、可启动、可备份和可恢复。
- 依赖许可证与 FFmpeg 构建配置没有未处理的分发阻断项。

### 必须暂停、缩减范围或新增 ADR

- 无法可靠阻止 `/library` 或媒体库根目录之外的读取。
- SQLite 在已确认目标规模上无法同时满足数据正确性与可接受交互，且调优后仍失败。
- 目标架构无法提供一致的 libvips/FFmpeg 能力或安全更新路径。
- 认证未实现且部署方案要求直接公网暴露。
- 核心依赖存在无法接受的许可证、专利、供应链或未修复高危漏洞问题。

触发 No-Go 不等同于放弃项目。优先缩小格式、规模、架构或网络暴露范围；若需要引入外部数据库、独立 worker 或改变路径模型，必须先新增 ADR。
