## 已验证

- 默认设置禁用、回收站开启且手动清空；独立部署开关 `FOLIOPATH_MEDIA_MUTATIONS` 默认关闭。缺少部署授权时不启动变更子进程，缺少内核能力或只读挂载时不接受写入。
- 新接口进入现有会话和 CSRF 边界，统一错误信封，私有路径、来源身份、回收定位符和原始系统错误不对外暴露。
- 持久化回收与恢复保留 ID；原路径替换获得新 ID、不继承旧收藏；永久清理旧条目不删除新资产。
- 部分永久删除暂停后，经正式扫描校准实际剩余树再恢复可见性；旧 claim 无法继续提交。
- 429 条目的清空分批物化；暂停、后续清空、后来加入及忙碌后返回的条目不会扩张原范围。
- 保留策略变更撤回排队中的到期清理；正常关闭按 fence 归还、取消优先；三次崩溃后不自动重启操作。
- 真实 Linux 子进程在 intent、文件移动后但结果未记账、目录元数据部分更新三个阶段被 SIGKILL；重新打开 SQLite 后能完成恢复并保留原资产身份。
- 新编译的 Linux arm64 开发二进制在已有运行时、临时 Linux 数据/媒体卷中，通过完整 HTTP 认证/CSRF、默认禁用、启用回收、重复提交、恢复、永久删除、未索引文本随目录处理以及库根保留。该二进制为 `CGO_ENABLED=0`，只证明本次文件/HTTP/任务链，不能替代生产 libvips 镜像验证。
- 库移除在排队、暂停和非空回收站期间拒绝，清理后才允许；真实 SQLite 回归和 HTTP 策略拒绝补验通过。
- 回收区创建实际遵守目录权限；测试卷准备显式授予权限，应用不执行 chmod/chown，也不增加 capabilities。

## 发布限制

`make test-e2e` 两次在拉取 Dockerfile frontend 时遭 Docker Hub EOF。使用内置 frontend 的临时等价构建继续遇到 Debian 仓库不可达，未完成生产 libvips 冒烟镜像验证。没有将其记为通过，也不以旧镜像替代新镜像结果。

S4 仍需生产镜像下的同二进制子进程验证、原生 amd64/arm64 配对、真实支持存储矩阵、同一挂载身份与备份恢复、四核 / 4 GiB 的约 100k 媒体 / 10k 目录容量证据及发布审查。不承诺固定清理速度；不宣称支持 Docker Desktop 宿主媒体写入或网络/FUSE/CD2。

测试源、夹具和输出只在本地保留，不增加 25 项发行例外。基础部署保持只读；可写部署必须独立显式启用。
