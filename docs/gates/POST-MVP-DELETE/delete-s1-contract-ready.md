## 权威合同与所有权

- HTTP：[`api/openapi.yaml`](../../../api/openapi.yaml)；生成客户端通过现有生成流程产生。新增端点使用同一错误信封，新增错误值限于 `DeletionErrorCode`，不扩张旧接口的封闭错误枚举。库移除约束使用现有 forbidden 策略拒绝及安全提示，不冒充幂等冲突。旧 `readOnlyMedia: true` 保留并废弃其能力判断用途；删除授权以专门设置接口为准。
- 数据：[`00049_media_deletion.sql`](../../../migrations/00049_media_deletion.sql)，不修改已发布迁移。设置、确认凭据、幂等请求、操作、条目、租约、恢复阶段与审计保存在 `/app/data`。私有回收载荷留在同一媒体文件系统。
- `internal/deletion` 拥有策略、确认、任务及恢复用例；SQLite 拥有其持久事务；`files` 独占媒体变更；`app` 组合；复用 `jobs.WorkerPool` 和 `resourcecontrol`。
- 只允许删除、移入回收站和无覆盖恢复。不允许编辑文件内容、任意改名、复制后删除回退或浏览器命令。

## 有界执行与一致性

请求最多 200 个顶层目标，活动操作最多 32 个，查询默认 25 / 最大 50 项。一个媒体变更子进程同时占用一个共享后台槽和固定为 1 的变更槽；设置准备也遵守同一个变更槽。IPC 单消息最多 64 KiB；启动检查最多 5 秒；子进程生命周期最多 1 小时；每批最多 256 个删除目录项、128 层目录句柄。文件系统 I/O 不持有 SQLite 写事务。

队列保留可见性，条目开始时才激活统一隐藏范围。所有媒体查询、来源查找和派生提交引用 `visible_assets` / `visible_directories`；索引提示查询仍连接同一可见性视图。普通扫描不能越过活动或未决变更。失败扫描和离线根保留旧索引。

回收行保留资产 ID 与人工状态，使用内部路径命名空间释放原路径唯一性；原位置的新文件获得新 ID。恢复不覆盖、不合并、不自动创建原父目录。普通父目录重建后需先扫描；媒体库根或存储身份改变时转需处理，不自动把旧意图绑定到新根。

清空以条目上界和可用序列冻结范围，分批物化；新加入、确认时忙碌后重新可用的条目不加入旧范围。暂停保留该任务的预约，继续需重新确认，并沿用原范围。更早的清空任务优先拥有重叠条目。

保留期限默认手动，可选 7/30/90 天。策略变化撤回未开始的自动清理；已开始的任务在安全点暂停，已删除内容不能撤销。关闭权限不清空记录，不自动续跑旧任务。自动清理复用同一持久队列。

永久删除部分完成后，先通过 scanner 的正式准入执行只读校准，再释放隐藏范围；失败或离线保持需处理。回收/恢复结果未知时核对两边的来源身份。信号触发的正常关闭只在子进程和心跳退出后，按准确 fence 归还 claim 并记录 handoff；崩溃仍最多三次，之后需明确继续。

## Linux 写边界证据

同一 Linux arm64 内核、默认 Docker seccomp、无额外 capabilities、无网络的合成场景中：

- 复现旧父句柄在被移出媒体根后仍能 unlink/rename；加入 Landlock 后同样操作被内核拒绝。
- Landlock ABI 至少为 3；禁止媒体内容写入/截断和根外目录项变更。所有路径继续使用既有 openat2 边界。
- 正常回收、无覆盖恢复、分批永久删除、符号链接不跟随、库根保护和取消回收子进程通过。
- Landlock 被 seccomp 拒绝、只读挂载、嵌套 tmpfs、同设备且同 inode 的自 bind 均拒绝写入。没有降级路径。
- 父进程死亡信号与正常关闭均约束子进程生命周期。只继承固定语言和部署的动态库加载路径，不继承代理或模型配置。

测试只使用临时目录、临时数据库与临时 Linux 卷；测试源码和输出遵守本地专用规则。未证明原生 amd64、真实媒体、所有文件系统、网络/FUSE/CD2、存储迁移或容量档位；这些仍归 S4。
