## 用户问题与价值

- 用户 / JTBD：管理员需要通过可直达、可恢复的独立页面完成配置和运维操作，并把交互原型作为
  后续生产开发的明确 UI 合同。
- 当前问题及证据：原型把扫描与缓存、账户放在通用页锚点中，媒体库按钮没有行为；无法验证
  保存、校验、失败恢复和危险操作。
- 为什么必须进入目标版本：现有 MVP 已要求设置、媒体库、扫描、缓存、单管理员与退出登录，
  但缺少页面边界和账户维护合同会让实现与验收继续漂移。

## 范围

- 新增或改变的 FR/NFR：新增 `FR-AUTH-005` 和 `FR-UI-009`。
- 明确包含：四个独立设置路由；通用偏好；媒体库生命周期；扫描计划与任务；缓存配额与清理；
  管理员显示名称、密码和当前会话退出。
- 明确不包含：多管理员、角色权限、会话设备管理、忘记密码、邮件恢复、外部身份提供商。
- 被替代/延期的现有范围：不替代既有 FR；原通用页同页锚点方案被替代。
- Scope-budget exception：产品负责人于 2026-07-30 明确接受新增账户维护和独立页面的 MVP
  UI/API/测试预算；不得以削弱原文件安全、认证、路径边界或扫描一致性换取。

## 架构影响

- Capability 与依赖方向：规则仍由既有 capability 所有；Web 只能通过生成 client 和领域
  adapter 调用，不复制密码、路径、扫描或缓存策略。
- API / 用户流程：需要接受账户资料/密码 operation 与设置页面读写的 OpenAPI 合同；媒体库、
  扫描和缓存复用既有 operation。用户流程见 `docs/user-flows.md` 第 8 节。
- 数据 / migration / 派生状态：显示名称和密码哈希复用单管理员记录；若现有 schema 不足，
  通过向前 migration 增量扩展。缩略图缓存仍是派生状态。
- 安全、隐私与信任边界：修改密码必须验证当前密码、撤销其他会话并受 CSRF/限流保护；响应不
  泄露凭据、绝对路径或内部错误。
- 性能、容量与并发：设置写入使用 revision/ETag；同库完整扫描保持唯一；清缓存任务有界。
- 部署、升级、备份、恢复与观测：不增加部署单元或外部服务；密码/设置修改写审计友好日志，
  不记录秘密。
- 平台、依赖、许可证与供应链：N/A；不引入新依赖。
- ADR：N/A；不改变技术、部署、信任、持久化或模块依赖边界。

## 质量属性场景

- 刺激：管理员在任一管理页修改值、触发扫描/清理或提交无效/冲突输入。
- 环境：认证会话有效，可能存在并发设置版本、离线库、运行中扫描或磁盘压力。
- 系统响应：保持当前独立 URL 与用户输入；显示字段级或页面级可恢复错误；危险操作先确认；
  重复请求不创建并行副作用。
- 可测结果：刷新与前进后退恢复页面；键盘可完成主流程；四档响应式无隐藏控制；成功、冲突、
  认证失败、离线、取消和重试均有自动证据。
