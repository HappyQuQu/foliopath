# CR-2026-059 目录操作菜单与全部展开收起

2026-10-30；POST-MVP / NAV-S1 生产组件。用户要求左侧目录树增加全部展开/全部收起，并提出每行“⋯”可能拥挤，希望考虑顶部操作菜单及右键。当前设计基线为顶部一个菜单加桌面右键，不增加每行常驻按钮；已实现生产组件和浏览器验证，尚未发布。

- FR-BRW-016：当前媒体库目录树支持全部展开和全部收起；仅影响树的显示状态，不改变右侧目录/媒体内容、URL 或选择，不触发扫描。
- FR-BRW-017：目录标题右侧提供单个“操作 ▾”入口；桌面目录右键及键盘上下文菜单为快捷入口，移动端不依赖右键/长按。具体目标必须明确，不把整个树操作和文件夹删除混淆。
- Owner：browse 的 DirectoryNavigation 独占展开状态和菜单目标；共享 Menu/IconButton/焦点模式继续归设计系统，deletion 公共入口独占删除确认与请求。
- 合同：复用现有 OpenAPI 的目录列表、详情、游标及现有 query owner；不新增任意路径或文件系统读取。删除菜单项依赖 CR-2026-058 的 S1/S2，不能提前提供可点击但无法完成的删除入口。

## 菜单位置与目标

目录标题右侧只有一个“操作 ▾”按钮，目录行保留箭头、图标和名称。顶部菜单先列“全部展开”“全部收起”，分隔后显示“当前文件夹：名称”，再列该目录可用的动作。没有进入普通文件夹时明确显示媒体库名称，媒体库根不可删除；不把隐藏的上次右键目标当作顶部菜单目标。

右键某一目录时，在指针附近打开同一个菜单组件，目标是被右键的目录，标题显示该目录名称；不自动跳转、不改变右侧批量选择。菜单提供该目录展开/收起及可用的文件夹动作，整个树的全部展开/收起保留在顶部入口。点击空白位置仍为浏览器原生菜单。按 Escape 或点外部只关闭菜单；键盘可用 Shift+F10/上下文菜单键，关闭后焦点回到触发目录。

手机先点目录名进入目标，再从顶部操作菜单处理当前文件夹；选择即有明确目标，不增加另一套触摸长按规则。危险动作使用“删除…”进入按当前策略命名的确认窗口，分隔显示；整 ZIP/7z 标明整个压缩包，包内虚拟目录不提供删除。所有删除动作仍进入正式范围确认，菜单本身不直接删除。

## 全部展开与收起

“全部展开”作用于当前媒体库所有层级的期望展开状态。已知节点立即展开；未加载层级继续按既有分页及可见区域逐步加载，后来出现的节点沿用展开状态。不在点击瞬间启动全树抓取，不读取每个目录的原媒体，不为每个节点并发发起请求。大树必须采用有界可见行渲染和受限的目录加载准入，不能在现有递归组件上简单把所有 expanded 设为 true 后任其请求/DOM 无限增长。加载中/某分支失败真实显示，失败分支可重试，不能提示所有目录已加载完成。

“全部收起”立即收起所有子层级，保留媒体库根及第一层目录；撤销自动展开意图并停止继续为展开加载新分支，迟到响应可以进入既有 query 缓存，但不能重新展开树。正在浏览的右侧内容和 URL 保持不变，不为了让当前节点可见又立即重开其祖先；下次主动导航目录时再展开新路径。当前只有第一层或空树时，按钮状态需反映无可收起内容。

全部展开后仍可单独收起某分支，用户局部选择优先于全展开默认；再次点全部展开才重置局部收起。展开状态仅属于本库本次导航组件，不写后端、不保存完整目录树到浏览器存储；切库复位到新库当前路径，取消旧库自动加载。
