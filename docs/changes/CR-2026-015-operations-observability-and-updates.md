- 产品负责人：产品用户
- 架构负责人：FolioPath maintainers

## 用户问题与决定

用户不能从“已处理但有失败”的派生媒体进度判断失败对象、原因和恢复方式，也不能统一查看
后台进度、新版本、应用版本与发布记录。确认扩展既有 `FTR-OPS-001`：

- 完整扫描与派生媒体恢复保持两个独立操作；“重新扫描”不冒充失败任务重试；
- 派生进度显式区分成功和失败，失败数可进入安全诊断列表；
- 管理导航不再单列“扫描与缓存”：配置项收进“配置”的通用/扫描/缓存页签，扫描历史和
  派生结果收进“媒体库”的媒体库/扫描记录/处理结果页签；旧 URL 只作深链兼容；
- “系统日志”只展示结构化、分页、脱敏的应用生命周期、管理员写操作、请求拒绝和服务端错误，
  不再混入扫描记录或逐媒体处理结果，也不公开原始 stderr/SQL/stack；
- 管理中心增加“系统日志”和“关于”；关于页展示构建版本、版本历史与安全更新检查；
- Header 消息中心聚合进行中、需处理、最近完成和版本提醒；清除完成消息只改变通知可见性，
  不删除任务或日志事实。
- 媒体失败按一个聚合事件计入角标；用户进入结果或确认后保存最新失败水位，新失败出现时再提醒，
  活动任务始终保留且不可确认隐藏。
- 消息中心对活动派生任务显示已处理/总数、排队、处理中与失败，并在活动期间每 1.5 秒刷新；
- 媒体库的“扫描记录”复用 canonical `scan_runs`，其“处理结果”读取逐文件 `media_jobs`
  失败事实，不建立第二套扫描状态；
- 媒体库列表的状态查看在当前行下方展开，避免遮罩和查看/返回造成上下文、滚动位置丢失；
  行内展开区是完整查看界面，不再提供二次跳转入口；列表行不重复提供扫描按钮，重新扫描、
  补齐缺失、全部重建和取消扫描统一位于展开详情底部；旧状态页路由仅保留兼容既有深链接。

## 架构与数据影响

scanner、thumbnail、release information 继续拥有各自状态；HTTP 聚合不得建立第二套 worker
状态机。首个纵向切片直接查询既有 `scan_runs`、`media_jobs`、`assets` 与 `libraries` 的任务和
结果事实。为回答“具体哪一步失败”，migration 18 为每个既有 media job 有界保存最近 10 次
结构化尝试（阶段、稳定原因、工具、退出码、耗时），不复制媒体路径或原始工具输出。管理员
手动选择“补齐缺失”时纳入未生成、缓存丢失和全部失败结果；“全部重建”经确认后纳入全部
成功和失败结果。两种操作均以每次最多 256 项的短事务持续接纳，invalid/unsupported 只停止
后台自动循环重试，不阻止管理员显式操作。
migration 17 只追加有界 `system_events`，保存稳定事件码、级别、模块、route pattern、状态码、
耗时和 request ID，最多保留 5,000 条；它不保存任意错误文本、请求参数、媒体路径或凭据。

版本号继续由构建参数注入。发布记录使用仓库内唯一、可验证的版本清单生成应用历史和正式
Release 内容；更新检查失败不得影响启动、浏览或扫描。首版只提醒容器管理员，不在应用内
替换镜像或执行部署命令。

## 安全与资源边界

- 所有新 API 仅限认证管理员，写操作继续要求 CSRF；
- 诊断只公开媒体库 ID、任务/资产 opaque ID、library-relative path 和稳定错误码；
- 不公开宿主路径、allowed-root-relative library root、SQL、stack、errno 或媒体工具原始输出；
- 列表使用 keyset cursor，默认 50、最大 100；重试 admission 每次最大 256；
- 每个 media job 的 attempt history 最多 10 条，不保存 stderr、命令行或绝对路径；
- 更新检查使用短超时、缓存和失败降级，不成为 readiness 依赖。

## 验收

- 34 个终态失败显示为“成功 + 失败”，并能逐项解释原因；
- 诊断启用后的失败可行内查看每次尝试的阶段、稳定原因、工具、退出码和耗时；旧失败明确提示
  重新处理后才能采集详情；
- 重试只重新接纳 transient failure，不循环处理 invalid/unsupported；
- 日志过滤、分页和详情不泄露敏感路径或原始工具输出；
- 消息可跳到对应任务/日志/更新页；失败按一组计数并可确认，确认后新失败会重新触发；活动消息
  不能被“一键清除已完成”或确认操作隐藏；
- 活动派生任务在消息中心持续更新聚合进度；失败消息直接打开媒体库处理结果；
- 媒体库的扫描记录与处理结果使用独立、可直达的 URL 视图；系统日志可按级别和模块筛选；
- 无网络时关于页仍显示当前版本和内置发布历史，更新检查明确降级。
