# CR-2026-054：预览布局与精简拍摄信息

- 用户于2026-10-28明确请求优化右侧预览布局并显示EXIF。
- 目标：POST-MVP-5 后续维护版；S0只读合同 → S1后端和集成验证 → S2正式组件/Story/UI验证。不是把完整EXIF面板移入MVP。
- 需求：FR-EXIF-001（选中图片按需显示拍摄时间、相机品牌/型号、镜头、光圈、曝光时间、ISO、焦距）、FR-EXIF-002（无数据不造值、失败可重试）、FR-EXIF-003（仅源绑定只读、固定字段、有界并发/输出）；沿用FR-MED、FR-UI-001～003/006与NFR-UIF-001。
- owner：media 的只读ExifService；imagevips从已打开的流读取固定标签并规范化；API映射DTO，app唯一组合；media feature通过生成客户端/Query拥有拍摄信息，预览与查看器以slot组合，不让shared层访问API。
- 合同：GET /api/v1/assets/{assetId}/exif 返回最多8个固定key/有界纯文本value。空数组表示没有可显示的字段；沿用认证、内容读取准入及固定错误。无GPS、序列号、原始EXIF blob、HTML或宿主路径。
- 原件经过ContentService/files边界打开，读取前后核对源；复用imagevips原有内存准入和有界可取消读取，不解码/导出图片，不改变像素、缩略图或AI身份。仅按需读取、不写SQLite、不扫描重处理、不引入新的部署/事务/调度owner。
- 布局：纠正把左侧工具栏高度叠加到右侧预览的定位错误；预览紧贴面包屑下方，压缩头部/导航，将完整查看器入口移至头部图标，图片区域随屏高适配，让基础信息与拍摄信息获得更多空间。
- S0：本记录与OpenAPI合同先于生产UI编写；后续阶段以执行结果补齐。

- 兼容性审查：仅新增认证只读GET与独立AssetExif响应，不修改任何既有路径、schema、写入或权限语义；现有客户端无需变化。审查后更新api/openapi.sha256。
- S1：服务/HTTP测试通过；原生libvips合成JPEG八字段与无EXIF读取通过，拍摄时间不添加时区；序列号未返回。
