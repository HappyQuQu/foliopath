## 接受的行为

1. 同页按assetId将照片合并展示，同一照片的人脸用粗略框及等价单选标记明确选择，默认不选；页内标记不是模型ordinal或现实身份。memberCount是人脸数，不冒充照片数，页内人脸与不同照片数量分别显示。
2. 移除旧的浏览器循环多项提交，改为一次只确认一张人脸。确认框冻结face修订号及目标人物修订号；不在确认后再抓新版本，不静默重试或用新版本覆盖冲突。
3. 新建空人物与人脸归类分两次明确动作；创建成功不冒充已归类。原groupAssignmentAllowed质量门禁不放宽，不调用整组创建/归类。创建不确定响应的显式重试复用同名称幂等键，防止重复建人。
4. 成功/未确认保存/冲突/读取错误各自显示；刷新导致分组变化时保留保存结果和返回列表入口，不把分组读取失败解释为没有人脸。
5. 需求/流程/UI/正式Story使用同一实现；390/768/1440/1920、中英/深浅、键盘/axe、取消/双击/冲突及真实模型合成Docker验证。原6010与原库人工整理不参与写入；10源文件继续跳过，不连接server222。

本轮不提供批量整组事务、自动命名/自动合并或质量校准；完整人物目录、OCR、容量/发行仍独立。状态：2026-10-25本切片开发及最终本地Docker验收完成，原6010未部署此版，不冒称全部AI完成。

## 既有合同的重要边界

- 分组成员是持久化相似结构，人工归类/排除不保证立即移除其中成员；只靠FaceClusterMember无法判断是否待处理。正式页面同时消费既有AssetFace状态，只允许anonymous_core/anonymous_edge/unclustered且修订相符者操作。已归类/已排除项保留只读显示，不伪造分组总“待办数量”。
- 新建人物不携带sourceCluster。创建与人工单脸归类分成两次动作，不能把第一步成功宣称为整组成功；groupAssignmentAllowed门禁保持false时，真实合成测试仍只走明确人工单脸路径。
- 空人物创建的不确定响应重试保留同名称的幂等键；单脸审核保留同一确认快照/键以供显式重试。冲突不自动重发，后一个独立确认才读取刷新后的目标版本。
  该确认对象保留于当前页面会话，不宣称刷新浏览器后仍能恢复未确认请求；刷新后须先核对人物/人脸的真实状态。
- 整组批量命名/循环提交改为明确单脸操作；这是安全与反馈语义收口，不声明后台新增原子批量接口。分组列表仍是相似分组目录，未新增全库未处理分组筛选/总数合同。
