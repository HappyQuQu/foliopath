## 变更

以官方 [Node 24.22.1 LTS](https://nodejs.org/en/blog/release/v24.22.1) 及发布索引
`https://nodejs.org/dist/index.json` 核实当前 24.x 最新版本，配套 npm 11.19.1。
固定本地 Node 为 24.22.1，包 engines 接受 `>=24.22.1 <25`，npm 使用 11.19.1，
类型声明同步到 `@types/node` 24.19.2。lockfile 由配套 npm 重新生成。

Docker 使用官方 `node:24.22.1-bookworm-slim`，固定多架构 index digest：
`sha256:55fb5f5a527ea2c5c4a95f963e48ef90aa38c7b346054fdc8ee9957a2b55d205`。
实际拉取并运行确认 `node --version` 为 `v24.22.1`、`npm --version` 为 `11.19.1`。
Node 用于前端构建，最终 Go 运行时、媒体访问、数据库和部署挂载保持既有合同。
历史 Node 22 验证记录仍描述原执行环境，不改写为本次新证据。

`make arch-check` 增加开发版本、engine、lockfile 和 Docker pin 一致性检查，
防止再次出现开发机与 Docker 前端构建层补丁版本不一致。

## 验证

以下均在 Node 24.22.1 / npm 11.19.1 下执行成功：

- `npm ci --prefix web`、`npm run build --prefix web`。
- `npm run check --prefix web`：high audit、生成漂移、架构/视觉引用、类型检查、
  47 个文件 / 172 项前端测试、Storybook 构建全部通过。
- `make fmt`、`make arch-check`、`make generate-check`、`make lint`、`make test`、
  `make test-integration`、`make test-e2e`。
- `docker buildx build --target web --output type=cacheonly --progress plain .`：
  使用固定 Node 24 镜像和生产 Dockerfile 的前端构建阶段通过。
- `docker run --rm node:24.22.1-bookworm-slim sh -c 'node --version && npm --version'`：
  确认容器工具版本。
- `git diff --check`。

Docker 首次解析 Dockerfile frontend 时遇到 Docker Hub token endpoint EOF；重试后
上述 Docker 构建及应用容器 smoke 均成功。原生双架构正式镜像发布结果待补录。
