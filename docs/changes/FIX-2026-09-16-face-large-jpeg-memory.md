# P4 大 JPEG 人脸预处理内存修复（双架构小样本复验）

范围：CR-2026-030 / FR-INT-009 / NFR-INT-002、003 / POST-MVP-5 P4；Owner imagevips/app/测试。对应小样本远端 OOM，不新增产品能力、API、表或部署单元，媒体仍只读。

已复现：原解码器处理远端匿名副本序列，在 sample-062.jpg 前后触发本地 Docker 768 MiB OOM/137；该文件单独处理通过，不能声称它是唯一坏文件。普通/旋转 JPEG、PNG、渐进 JPEG 的单一合成内容在相同限制下通过，说明只测单一图片不能覆盖序列内存行为。

已撤回失败候选：按目标尺寸改变全部 JPEG shrink 倍率仍 OOM，不保留该算法变化或试验中的 input-v2 指纹。单独关闭操作缓存、设置 GOMEMLIMIT=128MiB、限制 malloc arena/trim、线程缓存清理也不足以让原序列在 768 MiB 全部通过。

当前候选：JPEG 先用有界字节流读取尺寸头部，在第一次 native load 前设置**原有 >100 MP shrink 规则**，不再先完整打开再重新打开；输出算法/限制及 input-v1 身份不变。禁用 native operation cache，避免跨输入保留 native 资源；独立合成组合曾在旧缓存下 OOM，关闭后通过。测试资源从 app 768/AI 2560 MiB 调整为 app 1024/AI 2304 MiB，合计仍 3328 MiB，CPU 1+3 不变。只是增加旧主应用到 1 GiB 仍失败；候选代码＋新分配才完整处理同一序列。不是增加整机预算来掩盖失败。
