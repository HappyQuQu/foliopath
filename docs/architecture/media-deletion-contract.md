> 2026-10-30 后续用户决定：新删除直接永久删除，仅一次弹窗确认，不再输入确认词或额外勾选；移除回收/保留期设置，移除回收站页面与接口，历史文件及记录不自动清理。文件管理统一管理中心样式。当前基线见 [CR-2026-060](../changes/CR-2026-060-direct-deletion.md)。旧回收设计和阶段记录保留为历史。

# 媒体删除与回收站方案

> 当前执行决策以 [ADR-0044](../adr/0044-simple-media-deletion.md) 为准：撤掉 Landlock/隔离子进程，不改 PVE；222/9090 本次获准候选升级并启用删除和回收站。下文 S1～S3 验收状态为此前记录，通用 S4 发行门禁仍保留。删除时外部程序不能移动同一目录或其父目录。

2026-10-30；[CR-2026-058](../changes/CR-2026-058-media-deletion-and-trash.md) / ADR-0042/0044；目标 POST-MVP / DELETE。S1 合同和本地 S2 后端已通过，允许 S3 生产组件开发；222/9090 按用户明确授权走独立候选部署；通用双原生、容量及正式发布仍等待 S4。HTTP 以 `api/openapi.yaml`、存储以 migration 00049 为准；证据见 [S1](../gates/POST-MVP-DELETE/delete-s1-contract-ready.md)、[S2](../gates/POST-MVP-DELETE/delete-s2-backend-ready.md)。

删除采用一次批量提交、服务端后台执行。开启回收站时整目录移入同一文件系统的保留区；关闭时直接后台删除。浏览器只处理用户选择的顶层对象，不展开或逐项提交文件夹内的全部文件。快速反馈、可恢复与实际释放空间分别表达，避免“页面消失”被误认为“磁盘已清空”。

| 需求 | 行为 |
| --- | --- |
| FR-DEL-001 | 支持单个或批量物理文件、物理文件夹删除；包含空文件夹、视频以及可识别但不可读取的整 ZIP/7z 文件 |
| FR-DEL-002 | 实例级“允许删除原文件”默认关闭；需可用的写入部署能力及管理员明确开启 |
| FR-DEL-003 | 实例级“使用回收站”默认开启；关闭后新删除直接永久删除，现有回收站条目不受影响 |
| FR-DEL-004 | 保留期限默认“手动清空”，可选 7/30/90 天；可分页查看、批量恢复、永久删除和清空回收站 |

| FR-DEL-006 | 恢复到原媒体库原位置，保留未清空内容的收藏、人工标签、标签移除抑制及人工人物关系；不覆盖、合并或自动改名 |
| FR-DEL-007 | 普通浏览、搜索、收藏、标签、人物、缩略图和内容读取统一排除已隔离/回收项；删除提交后不再被扫描或旧派生任务复活 |

| FR-DEL-009 | 删除设置变化不重解释已提交任务；关闭删除权限停止后续文件系统变更，保留待处理日志供显式恢复 |

| NFR-DEL-002 | durable intent、幂等与分批事务；断线、进程终止和磁盘/权限故障不把未知结果变成成功或重新删除同名新对象 |

首版不提供上传、内容编辑、任意移动/重命名、去重删除、跨库恢复、回收站逐文件展开、覆盖式恢复或多用户权限系统。不新增选择“所有搜索结果”的无界删除；“全选”只选已加载且可选的项目，明确数量，每个请求最多 200 个顶层对象。

ZIP/7z 虚拟根的动作明确命名“删除整个压缩包”，删除的物理对象是原包；包内图片和虚拟子目录没有删除入口，服务端也拒绝。不能把选择一张包内图片静默升级为删除整个包。选物理父文件夹会同时删除其中全部压缩包，确认窗口说明整个文件夹的范围。

## 权限和设置交互

设置页增加“文件删除”区块，和缩略图缓存清理分开。设置是实例级，不随当前媒体库选择改变。已有媒体挂载、数据卷、AI 部署均不自动切换。

| 状态或操作 | 页面行为与后台含义 |
| --- | --- |
| 未配置写入部署 | 删除功能关闭，说明“当前部署仅允许浏览，请先配置媒体写入权限”；不显示可成功保存的启用开关 |
| 媒体挂载只读或运行用户无权限 | 功能不可用，说明请检查媒体目录权限；不自动 chmod/chown/remount，不递归预扫整库权限 |
| 写入部署就绪，首次启用 | 确认“允许 FolioPath 删除原文件”，说明文件夹操作包含所有内容；保存后才出现删除入口 |
| 关闭“使用回收站” | 单独确认“之后删除将无法在 FolioPath 中恢复”；不触发清空，不改变已有任务；已有条目继续可查看、恢复或清理 |
| 缩短保留期限或首次启用自动清理 | 先显示按条目时间计算的当前到期条目数量和新规则，确认后生效；不通过递归统计文件数/字节阻塞设置 |
| 关闭“允许删除原文件” | 禁止新删除、恢复和清空，自动清理暂停；运行任务协作停在下一文件操作/批次边界，已做部分不回滚；页面保留查看和待处理状态 |
| 再开启删除权限 | 展示中断任务，让用户显式继续；不自动恢复永久删除。到期清理也需在该次启用确认中明确恢复 |

应用启用不能绕过部署授权；部署授权由未来显式 Compose 覆盖和配置提供。应用权限关闭不代表主容器已失去操作系统写权限，需要物理只读隔离时仍应恢复只读挂载。操作请求绑定当前删除策略版本及明确模式；设置变化使尚未提交的确认过期，要求重新确认，不将“移入回收站”改成“永久删除”。

保留期限从成功移入时间计算。关闭回收站只决定新删除的路由，已经启用的旧条目到期清理仍按其明确的保留策略进行；关闭整个删除权限则全部暂停。永久清理开始后该条目停止提供恢复，不提供后台抢占恢复。

## 浏览和批量选择

左侧目录操作入口采用[CR-2026-059](../changes/CR-2026-059-directory-tree-actions.md)：目录标题右侧一个“操作 ▾”菜单，桌面补充目录右键/键盘上下文菜单，不在每行放“⋯”。顶部区分整个目录树的展开/收起与具名当前文件夹动作，右键只作用于被点目录；两处删除均复用本方案确认用例，不能直接执行删除。

1. 批量勾选放在右侧主内容区，左侧目录树只负责导航，不增加复选框。主内容工具栏右侧提供“选择”按钮，手机在主内容工具栏保留同名按钮；默认不显示复选框，不依赖长按或鼠标悬浮。目录树的单目录菜单、侧预览及查看器仍可直接进入同一个单项删除确认；首版不增加 Delete 键一键永久删除。
2. 点击“选择”进入选择模式，右侧文件夹卡片和媒体卡片显示复选框。点击卡片或复选框均只切换选择，不打开目录、预览或查看器；退出选择模式后恢复原点击行为。工具栏显示“已选 N 项”、选择当前列表、清除选择、删除和“退出选择”；“退出选择”退出模式并清空选择，不执行删除，零选择时删除禁用。“选择当前列表”仅包含当前已展示的可选项，显示实际数量并遵守 200 项上限，不代表全部搜索结果。按稳定 ID 选择，不以列表位置选择；选择跨已加载分页保留，切换媒体库、目录或搜索条件时清除。多库搜索可批量选择多个库的普通文件，每项保留所属库。只读/离线/归档成员标明不可选原因，复选框具备名称和键盘焦点。
3. 选择父文件夹时，后端按规范路径去掉其内重复选择的文件夹/文件。确认结果显示实际顶层数量及有界名称列表；不让前端维护另一份递归去重规则。
4. 不允许删除 `/library`、任一媒体库根、回收区或其祖先。媒体库根的删除不可用，移除配置仍在媒体库管理中处理；全删库内内容需明确选择库内对象，不能把移除媒体库变成删除目录。
5. 打开确认框调用预检，读取当前策略和顶层实际来源。离线、目标已变、任务占用等逐项显示，默认不跳过后悄悄执行。用户可移除受阻项重新预检；有效提交后才允许出现运行期部分成功。
6. 预检只验证顶层及已有目录统计，不遍历全部文件。目录确认按执行时该目录内的全部内容生效，提示“包含其中所有文件和子文件夹，含未显示的文件”；已有媒体数量若展示应标为“已收录媒体”，不当作真实总文件数或保证删除大小。

| 确认框 | 主按钮 | 必须说明 |
| --- | --- | --- |
| 回收模式 | 移入回收站 | 顶层名称/库内位置、完整目录范围、是否自动清理、清理前可恢复、暂不释放空间 |
| 直删模式 | 永久删除 | 相同范围，并明确原文件会被删除且无法在应用内恢复；首版统一要求输入本地化确认词，不依赖未知文件数决定危险等级 |
| 归档根 | 移入回收站 / 永久删除 | 明确是整个 ZIP/7z 及包内所有内容，不能只写“删除文件夹” |

预检读取期间确认按钮禁用；失败保留选择并允许重试。确认框默认焦点为共享 Dialog 的非危险关闭控制，提交后禁用重复点击。已提交后的关闭只关闭界面，不取消后台任务；提交响应丢失时用原幂等键查询/重放，不能重新生成删除意图。服务端操作列表可在刷新、换设备后找回任务，本地提示不承担持久队列职责。

## 删除中的页面与任务

HTTP 持久入队成功返回任务引用；提示“已提交删除任务”，不能提示“已删除”。排队期仍显示被选对象并标为等待处理，避免用户把尚未发生的文件操作当成功。任务开始前先持久隔离目标子树，随后普通内容投影隐藏该子树，不等待几万条关联清理结束。

- 回收移动确认成功：提示“已移入回收站”，提供“查看回收站”和单次恢复入口；恢复入口提交同一个正式恢复用例，不维护独立 toast 撤销逻辑。
- 永久删除：任务页显示当前顶层文件夹、已完成顶层数、已处理文件/目录数和失败数；未知总量使用不定进度，禁止用已收录媒体数计算百分比。
- 多项部分失败：逐项保留结果，重试只包含未完成项；已经回收/删除的项不重做。没有完成文件操作的失败项解除隔离后重新出现；部分永久删除先定向校准剩余内容，再解除隔离，并显示“部分内容已永久删除”。
- 选中的预览被隔离时关闭并回到集合；查看器可转到已加载且可访问的下一项，没有下一项则关闭，不为寻下一张无限翻页。删除当前所在目录后回到最近仍可访问的祖先，直到媒体库首页；URL、目录树与面包屑同步更新。
- 其他标签页通过现有 catalog 通知/刷新机制更新。旧游标按既有失效方式恢复；列表、收藏、搜索、人物结果及封面使用同一可见性规则，不只从当前页面数组删一项。
- 新内容/缩略图请求对隔离项不可用；已经开始发送的内容流不承诺收回已发送字节。首次实现不强行终止与删除无关的播放或分析任务。

文件管理工作区的任务页复用现有 shell、分页、状态和确认原语，提供等待、处理中、已停止、部分完成、完成、失败及需检查状态。排队或处理中可“暂停”，保留任务供显式继续，解释已完成项不会恢复。回收一个目录的 rename 一旦成功，该项只能通过恢复撤回；直删停止也不能找回已 unlink 的部分。UI 只显示用户原因及下一步，内部状态码、路径、租约和源身份只在服务诊断中。

## 回收站和恢复

导航新增实例级“回收站”，可按媒体库筛选，使用 URL 状态及游标分页。桌面列表使用可用宽度，手机改为条目卡，名称/原库内位置可换行；所有选择、菜单及确认支持键盘和可见焦点。

每个顶层删除目标对应一条回收记录，显示名称、所属媒体库、原库内位置、删除时间、清理时间或“手动清空”、可恢复/清理中/无法访问状态。不递归展开目录或为精确占用量扫描整个回收站；媒体原件不在回收站里直接播放/预览。可显示已知统计并说明不完整，不能把它当磁盘已释放量。

| 恢复场景 | 固定行为 |
| --- | --- |
| 原父目录存在、原位置为空 | 整项移回原位置，不覆盖；后台恢复关联/定向校准后重新公开 |
| 原位置已有同名文件或文件夹 | 留在回收站，提示“原位置已有同名内容，请先处理后再恢复”；不合并、不覆盖、不自动添加后缀 |
| 原父目录也在回收站或已被外部删除 | 留在回收站，提示先恢复或重建父文件夹；不自动创建任意目录 |
| 文件源被外部改动 | 原件能移回时仍验证来源；来源不匹配的 AI/人脸派生结果不复活，人工来源绑定按原 owner 规则待复核 |
| 库离线、权限不足、条目已经丢失 | 不伪造恢复成功；保留记录并给重试/检查存储的操作，不把根不可读当成全部丢失 |
| 恢复和到期清理同时请求同一项 | 事务内只能一方取得操作权，另一方得到当前状态；开始永久清理后不再允许恢复 |

批量恢复允许运行期部分成功；提交后退出选择，失败项及原因保留在文件任务明细，可处理原因后按原范围继续。恢复后尽量保留原资产 ID 和人工整理；AI/缩略图是否可复用由其既有源指纹与当前模型/变换 owner 决定，不能因为仍有结果就直接重新公开。

“永久删除所选”与“清空回收站”均需范围确认和确认词。清空绑定点击确认时已存在的有限条目上界，由后台分页处理；执行期间新移入的内容不被本次清空带走。清空/到期清理仍是永久删除，不保证释放等于文件大小的物理空间：打开的文件、硬链接及存储快照可能继续占用。回收站不替代备份。

## 后台所有权与存储

| Owner | 职责与不能越过的边界 |
| --- | --- |
| `internal/deletion` | 设置策略、顶层选择规范化、预检、删除/恢复/清理状态与错误映射，定义所需窄接口 |
| `internal/files` | 实际来源及目录锚定、保留区创建、无覆盖 rename、流式 unlink/rmdir、取消与固定文件错误；不拥有业务开关/队列策略 |
| SQLite adapter | 日志、幂等、claim/lease/fence、子树隔离、catalog 命名空间和分批关联事务；不执行媒体文件 I/O |
| catalog / scanner / search | 沿各自公开接口消费唯一可见性/变更屏障，不各写一套排除规则；继续拥有扫描代次和查询游标 |
| thumbnail / AI / curation / face | 既有源校验及 fenced commit 增加删除隔离检查；人工状态的具体修改仍由原 owner 定义 |
| jobs / resourcecontrol / app | 复用 WorkerPool、实例级资源预算和组合根；删除不增加外部 worker 或独立队列服务 |
| API / Web | API 仅调用 service；Web 一个 deletion feature 拥有适配、query keys、失效和确认交互，其他 feature 通过公共入口使用 |

数据库仅增加新迁移，设计字段如下，最终 SQL/索引在 S1 固定：

- 实例删除设置：允许删除、使用回收站、保留期限、单调 revision；部署能力单独读取，不允许 Web 修改实际挂载。
- 操作/幂等记录：opaque operation ID、模式/策略快照、请求键摘要、目标摘要、时间、状态、停止请求、claim/lease/fence、固定失败原因、到期清空上界。一个 operation 持有有界顶层 items。
- 操作项：库 ID、物理来源类型及库内路径、顶层源身份、原父目录、独立 trash entry ID、阶段/结果、已处理统计及有界遍历恢复信息。不接受用户提供的回收区目标路径。
- 回收条目：原库及位置、回收内部 locator、移入/到期时间、保留状态和关联 catalog 命名空间。UI/API 仅返回 opaque ID 与库内原位置，内部 locator 不公开。
- catalog：保留回收项对应的资产、目录及人工关系，增加回收命名空间和可见性。活动命名空间维持 `(library_id, relative_path)` 唯一；回收命名空间按条目独立唯一，使原位置出现新文件时可生成新资产 ID，不继承旧收藏/标签。不可仅在旧唯一约束上加 `trashed=true`。
- 子树隔离/变更屏障：短事务先登记顶层物理范围，立刻约束所有投影、扫描写入与派生提交；后代行分批迁入回收命名空间。迁移过程中禁止扫描同库，避免旧活动唯一键占位或新数据覆盖。恢复同样先隔离再分批还原，最后一次发布。

不把回收项的 catalog 行交给正常 stale-generation 清理，不在回收时触发资产 FK cascade。永久删除完成或确证某项已永久丢失后，由有界任务清理该项的 catalog、缓存引用与关联，更新人物/标签/计数/搜索修订；实例人物名称、全局标签及其他库关系保留。外部清空回收区只在根在线且可读时登记丢失，不自动猜测同名文件为原条目。

回收区固定为 `/library/.foliopath-trash/<instance-id>/<entry-id>/payload`，所有层均为普通目录。实例身份在 `/app/data` 中持久保存；不认领其他实例内容，不按名称猜测归属。整个 `.foliopath-trash` 从扫描、目录选择器、媒体 API、AI、封面与 watcher 校准中排除。若部署已有同名普通目录，启用检查报冲突，不接管、不删除。

删除任务/回收记录包含恢复所需信息，属于 `/app/data` 备份；媒体回收内容仍在原媒体存储中。不得按缩略图 LRU、data 空间水位或数据库记录年龄擅自删除回收内容；空间不足也不能静默跳过回收站改为直删。移除库受阻时必须说明有待处理/可恢复内容，不能通过库 FK cascade 清空真实回收文件。

## 执行与故障恢复

正常流程：认证/入口校验 → 验证预检选择和策略 → 原子持久入队 → 取得本库变更屏障 → 取得共享资源 → 隔离目标并登记文件系统意图 → files 操作 → 持久确认实际结果 → 分批整理 catalog → 解除屏障并发布刷新。文件 I/O 和媒体处理均不持有 SQLite 事务。

单个 worker 实例级串行执行媒体变更，初始并发为 1；排队上限初始 32 个活动操作（含等待/运行/停止待收尾），满时拒绝新任务并提示稍后重试。每请求 200 个顶层项，遍历/关联提交按最多 256 项短批次处理，边界可取消；不为每个文件创建 job 或每删一个文件提交一次数据库事务。清空是一个按快照上界分页的任务，最多与该 worker 共享一个活动清理任务，不一次把全部回收条目塞入内存。

| 路径 | 文件系统阶段 | catalog 发布阶段 |
| --- | --- | --- |
| 回收 | 记录独立目标及意图；整项无覆盖 rename；确认源/目标状态与持久性 | 保持隔离，分批把原 catalog 子树归入该回收命名空间，完成后确认回收成功 |
| 直删 | 记录顶层身份/直接删除意图；描述符相对的有界深度遍历，删除链接本身、不跟随链接；普通文件 unlink，子目录清空后 rmdir | 保持隔离，成功后分批清理对应派生/人工关联；失败或停止先校准真实剩余项再公开 |
| 恢复 | 占用条目，核对原父目录和位置为空；无覆盖 rename 回原位 | 原 ID/关联分批回到活动命名空间，定向校准及源复核完成后一次公开 |
| 回收清理 | 占用条目为不可恢复，之后复用同一有界删除路径 | 清理该命名空间及关联，写终态；不改变其他回收项 |

操作及条目状态由 deletion 唯一拥有；S1 固定 wire 枚举。内部区分 queued、running、stop_requested、reconciling、succeeded、partial、failed、cancelled 和 needs_attention；条目还记录 prepared/filesystem_applied/catalog_finalizing 等阶段。UI 的“完成”必须覆盖文件阶段和 catalog 收尾，不能只看 HTTP 返回或目录 rename 返回。

| 中断或错误 | 恢复规则 |
| --- | --- |
| 入队后响应丢失 | 原幂等键先查旧操作，再核对版本；相同意图不重复入队，不因首次预检已消费而拒绝找回旧结果 |
| intent 提交后、rename 前退出 | 原源仍匹配且目标不存在才可续作；对象已变化则停止核对，不能删除同名新对象 |
| rename 后、SQLite 确认前退出 | 依据固定源/目标和原身份核对，若目标是原对象则补记成功；不再对原位置执行第二次删除；两边冲突/都无法确认则转需检查 |
| unlink 一部分后退出 | 只恢复原操作范围和已登记的有界批次；重新读取剩余目录，核对顶层/条目身份，替换对象阻断；不存在仅对已登记意图视为该步骤完成 |
| 文件阶段成功、catalog 未收尾 | 保留隔离，重启继续元数据收尾，不重复做文件变更；只读回退部署也可完成已确认的数据库收尾 |
| 权限不足、只读、磁盘满或根离线 | 停止受影响项并保留日志；离线不授权清空旧索引；不自动改权限、不无限重试、不直删绕过回收站 |
| 进程强杀或租约失效 | 沿用 WorkerPool 有界恢复，先确认旧处理器已退出；数据库 fence 仅保护提交，不宣称能够撤销已经执行的文件系统调用 |
| 用户停止、关闭删除权限 | 下个协作边界停止文件变更；已发生部分必须完成记录/校准，不将停止写成回滚；后续继续需显式请求 |

回收 rename 需明确持久化语义，S1 在两种原生架构验证相关目录同步及崩溃点；SQLite WAL 提交不等于文件系统 rename 已耐断电。新文件替换、外部移动或清空的冲突一律保留需检查状态，不靠无界重试“修复”。不引入分布式锁/跨进程写入者协议；同实例内部一致性由既有单实例与短事务/本库屏障实现。

## 扫描及派生任务协作

删除/恢复取得本库变更屏障时，停止本库新扫描和 watcher 定向校准准入；运行中的扫描协作退出，不做 stale cleanup，等处理器退出再执行文件变更。其他库的扫描和正常浏览继续。屏障等待不占用资源执行槽，不与扫描形成互等。首版同库全扫描和媒体变更串行，不做逐目录并发锁优化。

开始隔离即推进可见性修订。所有 catalog/search/收藏/标签/人物/封面查询及内容 hydration 使用同一个隔离规则；缩略图缓存命中也不能绕过它。已在途的缩略图、语义、自动标签、人脸、OCR 任务在提交前检查隔离/来源，丢弃该子树的过期结果，按原任务 owner 处理跳过/取消，不把主动删除计为坏图或服务失败。

回收期间保留该命名空间的人工整理与派生数据，正常缺失补齐和扫描都排除它。回收完成后释放本库屏障，之后原路径出现的新文件属于新的活动资产。恢复先核对目标未占用，再保留原 ID 归回；来源/模型不再匹配时正常失效并重建。直删失败/停止对剩余文件做定向校准，再安排原定完整校准最终收敛，不能把部分删除当完整成功扫描。

## Linux 写边界和支持范围

files 的读取能力不获得通用写入方法，deletion 仅取得其明确需要的窄写接口。路径入口只用库 ID、资产/目录 ID 或 opaque 条目 ID，服务端解析物理来源；回收 locator 由服务生成。保留单媒体根、禁止嵌套挂载与符号链接逃逸，根和回收区保护不能只依赖 UI 禁用。

S1 验证描述符相对的源父目录与目标父目录、最终项类型/身份、`renameat2(RENAME_NOREPLACE)`、`unlinkat` 及目录移除。不能把既有用于模型缓存的路径型 `renameNoReplace` 直接当成媒体写边界，也不能用 `os.RemoveAll` 或 `sh -c rm ...` 绕过 files。只做 pathname precheck、随后用字符串写入不满足合同。

写入与外部程序同时修改同一目录的行为必须在 S1 明确：观察到替换/移动即停止，不能无提示操作新对象；现有 `openat2` 只约束打开时的解析，不能单独证明打开后目录被并发移走时的后续写入边界。原生可执行验证必须覆盖此差异并界定可保证的操作条件；证据不成立则该部署不启用写入，不以设备号相同或 realpath 检查冒充替代。

首版写支持目标是原生 Linux、同一普通本地文件系统且无嵌套挂载的媒体树，必须完成实际能力验证。SMB/NFS/FUSE/CD2、云盘、跨文件系统、Docker Desktop 媒体写入及非 Linux 开发适配器均不继承本地 rename 性能、故障恢复或安全证据；不支持时继续只读浏览。整目录移走的性能收益仅针对该支持范围，不承诺所有 NAS 挂载都近似即时。

技术依据：[rename 与无覆盖语义](https://man7.org/linux/man-pages/man2/rename.2.html)、[unlink/打开文件与空间释放](https://man7.org/linux/man-pages/man2/unlink.2.html)、[openat2 解析边界](https://man7.org/linux/man-pages/man2/openat2.2.html)、[Docker bind mount 写权限](https://docs.docker.com/engine/storage/bind-mounts/)。以上说明系统调用/挂载语义，不是本项目实现通过的证据。

## HTTP 合同设计

下表的接口已落入 `api/openapi.yaml` 并接入真实后端和生成客户端。OpenAPI 为 wire 权威，复用现有 session/CSRF、ETag/If-Match、Idempotency-Key、统一错误、keyset 和 opaque ID。

| 用例 | 已实现端点 | 合同要点 |
| --- | --- | --- |
| 读取/保存设置 | `GET/PATCH /api/v1/deletion/settings` | 返回部署可用性与原因、应用设置和强 ETag；PATCH 不修改部署配置 |
| 预检删除 | `POST /api/v1/deletion/preflight` | 最多 200 个带类型的资产/目录 ID；归档根由服务端确定物理原包；返回去重选择、模式、保留期、阻止原因及有界有效期的确认引用 |
| 提交删除 | `POST /api/v1/deletion/operations` | 原预检引用、明确确认、策略版本及幂等键；提交时重新核对，持久入队后 202，不在 handler 执行文件操作 |
| 任务列表/详情 | `GET /api/v1/deletion/operations[/{operationId}]` | 分页列表、条目结果及真实进度；任务不依赖浏览器 localStorage，空列表不是未知任务的成功证据 |
| 停止/继续 | `POST /api/v1/deletion/operations/{operationId}/stop`、`…/resume` | 状态版本保护，停止不回滚；resume 只对允许的未完成原范围，不重做成功项；未完成的任务仍沿原身份与范围继续，不自动改绑新源 |
| 回收站 | `GET /api/v1/trash` | 可选库过滤、稳定游标；只返回条目与原库内展示路径，不公开内部保留目录 |
| 恢复/清理 | `POST /api/v1/trash/restores`、`…/purges` | 有界条目 ID + 各自版本 + 幂等键；清理需确认词；原位置无覆盖检查在实际执行时再做 |
| 清空 | `POST /api/v1/trash/empty` | 显式范围、确认词、幂等键，绑定确认时条目上界，不清理后来加入条目 |

确认引用绑定顶层源/选择、模式、设置版本和有效期，不能当成任意文件写令牌。目录内后代并非预检快照，提交语义是已确认目录的执行时全部内容。确认引用过期或来源/策略变化不自动刷新后再提交；向用户说明变化并重新确认。多顶层项的入队在一次短事务完成，执行各项独立，不承诺跨目录文件系统事务回滚。

操作重复先按幂等键找原请求；同键不同意图冲突。队列满、库离线、写不可用、源变化、恢复冲突、条目清理中都必须有固定 domain error 和可操作的中英文映射，不把 OS 原异常、绝对路径、SQL 或内部身份返回用户。

必测场景包括：默认 ro 无写入；rw 但应用关闭无写入；单图/视频/空目录/整归档/多目录；父子去重、200 上界及多库部分失败；根/保留区/符号链接/嵌套挂载拒绝；隐藏和未收录文件的范围；回收后同名新文件不继承人工状态；恢复身份和冲突无覆盖；关闭开关不清空/不重解释任务；到期与恢复互斥；清空快照排除新加入；每个持久阶段 SIGTERM/SIGKILL；直删部分失败/停止后剩余校准；响应丢失原键恢复；扫描/缓存/搜索/人物/AI 旧提交不可复活；空间不足不绕过回收；库移除保护；离线不清索引；旧只读功能和源身份不变。

性能使用独立合成媒体树，覆盖 1 万、10 万文件，深目录、大平铺目录、多个顶层目录及包含非媒体文件的目录。对同类独立样本比较本机命令行、网页直删、网页回收，记录文件系统/存储、队列等待、202 返回、目录移走、catalog 收尾、完全清理、浏览延迟及峰值内存。暂定设计验收预算：空队列本地 200 项入队 p95 ≤1秒；回收整目录文件系统阶段不应随后代数量逐个增长。预算须由 S1/S4 数据核定，当前不宣称达标；直删耗时按文件数量增长是正常现象，不靠高并发掩盖。

`make arch-check` 已纳入唯一写 owner、生产默认 ro、AI 无媒体/data、新保留区不可扫描及读取/提交统一隔离的检查；其中只有代码结构项使用静态检查，行为用真实实现回归。测试、夹具和截图仍本地保留，不扩大 25 项发行输入白名单。完整相关验证沿仓库现有 make 入口执行并逐项记录，文档设计检查不代替后端或发行验证。

## 实现落点与当前限制

生产入口为右侧“选择”后勾选文件夹/媒体、左侧顶部“操作”菜单及桌面右键、查看器单文件删除。全局“文件管理”工作区统一提供回收站、文件任务、删除设置；从目录操作和通用设置进入。任务列表及明细每页 25 项，复用后台游标；选择只覆盖当前已载入范围，最多 200 项。媒体库移除依然只是配置移除，非空回收站或未结束操作会阻止它。

部署开关 FOLIOPATH_MEDIA_MUTATIONS 默认关闭；需要同一 /library 挂载可写、目录 DAC 权限和管理员开启。程序不会 chmod/chown，也不增加 capabilities。变更直接在既有 worker 内执行；取消在文件操作/批次边界生效，关闭句柄后释放资源准入。

遍历每批最多 256 项、深度最多 128；不做删除前全树计数。清空在提交时固定可用条目的序列上界，暂停仍保留范围预留，继续沿原范围处理；忙碌后返回或后来回收的内容不被纳入。数据库与文件系统身份不匹配时要求检查原存储，不自动将旧删除意图绑定到重新创建的媒体库根。

SystemStatus.readOnlyMedia 的旧常量字段为兼容保留并废弃，不作为删除准入依据；删除设置接口独占实际能力与原因。新端点使用独立错误码类型和原有错误信封。生产 libvips 镜像、amd64/arm64 配对、存储重启与备份恢复、100k/10k 容量和性能均未获 S4 证据。

## S3 落地差异与入口追踪

为保持名称明确，“完成”改为“退出选择”，语义不变。文件任务使用管理导航中的“文件管理”工作区，与扫描记录分开分页，所有业务状态仍由 deletion 后端拥有。目录操作、右侧批量选择、侧预览与查看器共用确认；不再增加一套媒体卡片“更多”菜单。提交成功后清空选择，运行期失败保留在持久任务明细，通过原任务继续处理剩余项，避免浏览器重建已执行范围。

| 页面控件 | 需求 | 合同 owner |
| --- | --- | --- |
