# FolioPath 需求确认清单

## 使用方式

本文把“已经接受的基线”和“仍需用户确认的产品选择”分开。推荐项只是当前建议，不等于已接受决定。可直接复制文末模板，将需要改变的字母替换后回复；补充文字优先于预设选项。

优先级说明：

- **P0**：开始对应模块实现前必须确认。
- **P1**：可以先搭骨架，但进入可用版本验收前必须确认。

## 已确认基线

以下内容已有明确用户意图、仓库约束或已接受 ADR，不重复询问：

- FolioPath 是 folder-first 的自托管图片与视频浏览器，不是备份、导入或文件整理工具。
- Docker 只划定一个只读 `/library` 媒体根和一个可写 `/app/data` 数据目录；媒体库及业务设置尽量在 Web UI 配置。
- 支持在设置中创建多个命名媒体库；媒体库是 `/library` 下受批准的目录并默认递归包含后代。
- 保留真实目录层级，提供目录树、面包屑、当前目录视图和递归后代视图。
- 拒绝相同、祖先与后代关系的媒体库根；扫描不跟随目录符号链接，也不允许路径逃逸。
- 文件系统是事实来源；SQLite、FTS 和缩略图是派生状态，只保存媒体库作用域内的相对路径。
- 原始媒体始终只读；移除媒体库只删除配置、索引、任务和派生缓存。
- 媒体库不可读时标记为离线并保留索引；失败、中断或部分不可读扫描不能清理旧索引。
- 完整扫描使用 generation，所有队列与并发有界，派生文件以临时文件加原子替换生成。
- 使用 Go 模块化单体、SQLite WAL、React／TypeScript／Vite、REST `/api/v1`、游标分页和虚拟化列表。
- 图片处理使用 libvips／govips，视频探测和封面使用 ffprobe／FFmpeg；MVP 不做视频转码。
- 单进程、单端口、嵌入式前端；未经 ADR 不增加 Redis、PostgreSQL、独立 worker、GraphQL、SSR 或 WebSocket。

## 待确认项

### RQ-001：稳定版认证边界

**优先级：P0**

- **A（推荐）**：开发预览版仅绑定回环地址或置于认证反向代理后；首个稳定版包含首次设置单管理员账号、会话与退出登录。
- **B**：稳定版也不内建认证，只正式支持部署者提供的认证反向代理。
- **C**：允许局域网无认证模式，并用高风险警告阻止误暴露公网。
- **影响**：决定用户／会话数据模型、首次启动流程、CSRF、限流、安全测试和首发时间。A 最符合“界面内完成设置”，但工作量最大；B 部署依赖更多；C 风险最高。
- **回复**：`RQ-001 A`、`RQ-001 B` 或 `RQ-001 C`。

### RQ-002：MVP 媒体格式矩阵

**优先级：P0**

- **A（推荐）**：图片索引与缩略图支持 JPEG、PNG、WebP、GIF；视频索引与封面支持 MP4、MOV、MKV，只有浏览器原生支持的编码直接播放。SVG、HEIC／HEIF、AVIF 与 RAW 暂不纳入承诺。
- **B**：在 A 上加入 AVIF 与 HEIC／HEIF 的探测、方向处理和缩略图。
- **C**：在 B 上加入常见 RAW 的预览图提取，但不做 RAW 编辑。
- **影响**：决定镜像编解码依赖、跨架构构建、文件魔数校验、测试夹具和“已索引但不可播放”的 UI。容器格式被索引不代表浏览器一定能解码其中的视频编码。
- **回复**：`RQ-002 A`、`RQ-002 B` 或 `RQ-002 C`，也可直接列出必须支持的扩展名与编码。

### RQ-003：默认排序与日期语义

**优先级：P0**

- **A（推荐）**：普通目录按自然文件名升序；递归与搜索视图默认按文件修改时间倒序。“日期”在 MVP 指文件修改时间，EXIF／容器拍摄时间后续加入。
- **B**：所有视图默认按修改时间倒序。
- **C**：MVP 即提取拍摄时间，优先使用 EXIF／容器时间，缺失时回退修改时间，并允许按两种日期切换。
- **影响**：决定索引字段、游标结构、元数据探测、时区与无日期媒体的回退规则。C 更符合照片时间线习惯，但增加格式和一致性复杂度。
- **回复**：`RQ-003 A`、`RQ-003 B` 或 `RQ-003 C`。

### RQ-004：目录树是否显示无媒体目录

**优先级：P0**

- **A（推荐）**：忠实显示所有可读取目录，包括当前没有受支持媒体的目录，并显示可用的直接／递归媒体计数。
- **B**：仅显示自身或后代包含受支持媒体的目录，让导航更紧凑。
- **C**：默认使用 B，但在设置中提供“显示空目录”开关。
- **影响**：A 最符合 folder-first，但系统目录较多时会显得拥挤；B／C 需要可靠维护后代聚合计数，并可能让刚创建但尚未放入媒体的目录不可见。
- **回复**：`RQ-004 A`、`RQ-004 B` 或 `RQ-004 C`。

### RQ-005：搜索默认范围

**优先级：P0**

- **A（推荐）**：默认搜索当前媒体库，并允许显式切换“当前目录（可递归）”与“全部媒体库”。
- **B**：始终默认搜索全部媒体库，再通过过滤器缩小范围。
- **C**：只支持当前媒体库；跨媒体库搜索推迟到后续版本。
- **影响**：决定搜索 URL、API 作用域、结果分组、空状态和跨库权限模型。A 功能完整但控件与查询组合最多；C 最简单。
- **回复**：`RQ-005 A`、`RQ-005 B` 或 `RQ-005 C`。

### RQ-006：定时完整扫描默认策略

**优先级：P0**

- **A（推荐）**：创建后立即扫描、应用启动时校准，并默认每 24 小时完整扫描；周期可在 UI 修改或关闭，手动扫描始终可用。
- **B**：默认每 6 小时完整扫描，适合变化频繁的目录。
- **C**：默认只在创建、启动和手动触发时扫描，定时扫描由用户主动开启。
- **影响**：频率越高，外部变更越快可见，但 NAS I/O、媒体探测和功耗更高。无论选择哪项，watcher 都不是正确性依赖。
- **回复**：`RQ-006 A`、`RQ-006 B` 或 `RQ-006 C`。

### RQ-007：隐藏项与系统垃圾目录

**优先级：P1**

- **A（推荐）**：扫描普通项和隐藏项，但默认跳过一小组明确的系统派生目录（例如 `@eaDir`、`.thumbnails`、`__MACOSX` 与回收站）；UI 显示跳过统计，后续再开放自定义排除规则。
- **B**：默认跳过所有以点开头的文件和目录，以及已知系统派生目录。
- **C**：除不安全符号链接和不支持媒体外不做默认排除，最大程度忠实文件系统。
- **影响**：A／B 可显著减少 NAS 缩略图与回收站重复内容，但内置名单可能隐藏用户确实想看的文件；C 最可预期但会增加噪声和扫描成本。
- **回复**：`RQ-007 A`、`RQ-007 B` 或 `RQ-007 C`，并可补充必须忽略的目录名。

### RQ-008：缩略图缓存上限

**优先级：P1**

- **A（推荐）**：在 UI 提供缓存配额，默认 10 GiB；达到上限后按最近最少使用顺序清理可重建缩略图，并始终保留安全余量。
- **B**：MVP 不设硬上限，只显示占用、提供手动清理并在磁盘空间不足时停止新任务。
- **C**：按 `/app/data` 可用容量自动计算动态上限，不要求用户配置数值。
- **影响**：A 可预测但默认值未必适合所有 NAS；B 实现简单但可能持续增长；C 体验自动化但磁盘余量与并发写入的规则最复杂。任何选择都不能让缓存耗尽破坏数据库。
- **回复**：`RQ-008 A`、`RQ-008 B` 或 `RQ-008 C`；选择 A 时可另给默认容量。

### RQ-009：默认画廊与交互方向

**优先级：P0**

- **A（推荐）**：内容优先的中性界面；桌面使用固定侧栏，移动端使用目录抽屉；自适应网格为默认、瀑布流可切换；仅在查看器、抽屉和直接操作中使用克制且可打断的 Apple 风格动效。
- **B**：瀑布流为默认，强调沉浸式图片浏览；自适应网格作为可选布局。
- **C**：密集文件浏览器风格，列表／紧凑网格为默认，视觉动效最少。
- **影响**：决定卡片比例、虚拟化测量、信息密度、移动导航和视觉验收基准。无论选择哪项，都必须支持键盘、减少动效与稳定滚动。
- **回复**：`RQ-009 A`、`RQ-009 B` 或 `RQ-009 C`。

### RQ-010：首发界面语言

**优先级：P1**

- **A（推荐）**：首发提供简体中文和英文，默认跟随浏览器，并允许在设置中切换。
- **B**：首发只提供简体中文，但从代码结构上保留国际化能力。
- **C**：首发只提供英文，中文在后续版本加入。
- **影响**：A 增加文案、布局和端到端测试量，但避免首发后再迁移硬编码字符串；B 最贴合当前主要使用者；C 更利于国际开源协作。
- **回复**：`RQ-010 A`、`RQ-010 B` 或 `RQ-010 C`。

### RQ-011：首版容量目标

**优先级：P0**

- **A（推荐）**：主要验收档为约 10 万媒体、1 万目录、4 GiB 内存的四核 NAS／家庭服务器；扫描期间浏览仍须可用。
- **B**：从首版即以约 100 万媒体、10 万目录、8 GiB 内存为主要验收档。
- **C**：先以约 2.5 万媒体、2 GiB 内存为验收档，规模优化进入下一阶段。
- **影响**：决定基准夹具、索引与聚合策略、扫描批次、缓存默认值和发布门槛。A 是覆盖常见个人收藏与控制首版复杂度之间的折中；B 会显著提高首发性能工程量。
- **回复**：`RQ-011 A`、`RQ-011 B` 或 `RQ-011 C`；如有真实媒体规模与硬件，请直接提供，它比预设档更有价值。

### RQ-012：媒体库名称与根路径修改

**优先级：P0**

- **A（推荐）**：名称必填且实例内唯一，允许改名；MVP 不允许原地修改根路径，更换路径通过“从 FolioPath 移除后重新创建”完成。
- **B**：名称只要求非空，可以重名；根路径仍不可原地修改，通过相对路径帮助区分。
- **C**：采用 A 的名称规则，并允许修改根路径；修改后废弃旧索引并执行一次完整重建。
- **影响**：A 最容易解释和恢复；B 会让切换器、错误和日志中的库难以区分；C 需要定义修改中状态、失败回滚、任务失效和大缓存清理。
- **回复**：`RQ-012 A`、`RQ-012 B` 或 `RQ-012 C`。

### RQ-013：是否允许取消扫描

**优先级：P1**

- **A（推荐）**：扫描详情提供“取消”，采用协作式取消；保留上次可靠索引和本次已安全提交的新增记录，并提示之后重新完整扫描。
- **B**：MVP 不提供取消按钮；扫描可离开页面且继续运行，管理员只能等待或重启服务。
- **C**：只允许取消手动和定时复扫，首次扫描不能取消。
- **影响**：A 对超大库和错误路径更友好，但需要任务状态、幂等、恢复和 UI 测试；B 实现较少，但误选大目录时体验差；C 规则更难解释。
- **回复**：`RQ-013 A`、`RQ-013 B` 或 `RQ-013 C`。

### RQ-014：MVP 查看器能力

**优先级：P0**

- **A（推荐）**：图片适应视口、缩放/平移、1:1、前后切换、全屏和基本文件信息；视频使用原生控件。不提供完整 EXIF 面板、显式下载按钮或移动端滑动手势。
- **B**：在 A 上加入常用 EXIF 信息和移动端左右滑动切换；仍不提供原文件编辑。
- **C**：精简为适应视口、前后切换和基本信息；缩放/平移与全屏推迟到下一阶段。
- **影响**：A 形成完整图片浏览闭环且范围可控；B 增加元数据、手势冲突和可访问性工作；C 最快，但对高分辨率照片的查看价值有限。
- **回复**：`RQ-014 A`、`RQ-014 B` 或 `RQ-014 C`。
