# FolioPath 开发就绪评审

## 当前结论

项目目前 **尚未达到功能开发就绪**，但可以开始阶段 0 的需求确认、验证性 spike 与必要的实验脚手架。通用产品脚手架在阶段 0 出口条件满足后进入路线图阶段 1。

当前仓库只有规划文档、许可证和 Agent 约束；尚无 `go.mod`、Go/React 源码、数据库迁移、OpenAPI、Makefile、Dockerfile、测试 fixture 或 CI。文档中写明的技术和功能均是目标，不是已经可运行的能力。

所有提案项在转为基线前应进入[需求确认清单](requirements-checklist.md)。架构约束变更还必须遵循现有 ADR 流程。

## 环境与工具链提案

以下均为**提案**，应在创建脚手架时固定版本和统一入口：

- Go 版本写入 `go.mod`，本地与 CI 使用同一 toolchain。
- Node.js 版本和前端包管理器通过仓库文件固定；包管理器仍待确认。
- SQL 使用 `sqlc`，迁移使用 Goose；生成命令必须确定性且可在 CI 校验。
- 系统依赖固定 libvips、FFmpeg/ffprobe 版本及构建选项，并记录 amd64/arm64 差异。
- Docker Buildx 构建发布镜像；SQLite CLI 可用于诊断，但应用不得依赖宿主机已安装 SQLite。
- 提供统一 Make 入口，目标与 `AGENTS.md` 一致：`fmt`、`generate-check`、`lint`、`test`、`test-integration` 和 `test-e2e`。

在这些目标创建前，不能声称运行过完整测试。目前文档变更只能执行 Markdown/链接检查（若工具已配置）和 `git diff --check`。

## 开发启动实施顺序

1. **关闭阻断需求**：确认支持矩阵、目标规模/硬件、网络暴露、日期定义和 MVP 验收标准。
2. **运行可行性 spike**：优先路径安全、generation/SQLite，再验证媒体处理、跨架构镜像与恢复；见[可行性研究](feasibility-study.md)。
3. **进入路线图阶段 1 后建立最小产品脚手架**：创建 Go 入口与 `internal/app`、React/Vite 入口、统一构建命令和基础 CI；不预建空业务包。
4. **契约先行**：新增首个 SQLite migration 与 `api/openapi.yaml`，生成 SQL/API 类型，并加入漂移检查。
5. **完成安全纵向切片**：只实现“列出允许目录 → 创建媒体库 → 安全扫描 → 索引一页媒体 → 返回缩略图状态”，全程使用合成 fixture。
6. **补齐故障路径**：验证重叠库、离线挂载、中断扫描、路径逃逸、损坏媒体和进程重启。
7. **容器化验收**：非 root 单容器运行，仅挂载 `/library:ro` 与 `/app/data`，演练健康检查、备份和恢复。

在纵向切片通过前，不并行铺开搜索、分享、EXIF、watcher 或其他未来功能。

## Definition of Ready

一个实施项只有满足以下条件才可进入开发：

- 对应需求有稳定编号、用户价值、范围和可观察验收标准。
- 所有产品/安全未决项已确认，或明确标为不属于本项并有负责人。
- API、数据迁移、UI 状态和错误语义的影响已识别；需要时契约先更新。
- 依赖项、外部工具、目标平台和所需 fixture 可获得且许可证清晰。
- 正常、边界、失败和恢复测试已列出，性能敏感项有已确认的测量环境与目标。
- 不违反 `AGENTS.md`、安全模型或已接受 ADR；如违反，替代 ADR 已先获接受。

缺少其中任一项时，工作保持“提案/待细化”，不得用实现细节替代产品决策。

## Definition of Done

一个变更只有满足适用条件才算完成：

- 实现与已确认验收标准一致，且不修改原始媒体、不越过路径边界。
- 数据库变化有只追加迁移，API 变化同步 OpenAPI，生成代码由源重新生成且无漂移。
- 单元、集成和必要的端到端/容器测试通过；执行过的命令与未执行原因准确报告。
- 路径、扫描、并发、媒体解析、错误脱敏和恢复等风险用例得到覆盖。
- 前端包含加载、空、错误、离线和键盘操作状态，且大列表继续使用分页与虚拟化。
- 用户可见行为、部署、安全、数据或架构发生变化时，相应 README/docs/ADR 已同步。
- 没有提交数据库、缓存、日志、Vite 产物或真实用户媒体；依赖和 fixture 许可证可追溯。
- 发布相关变更在目标架构容器中通过启动、健康、升级、备份与恢复门槛。

## 阶段 0 出场条件

- P0 需求已确认，MVP 范围、格式、认证、容量和验收口径没有架构级歧义。
- [可行性研究](feasibility-study.md)中的必做 spike 有可复现实验和结论，Conditional Go 已转为允许进入 MVP 实施，或范围已明确缩减。
- [风险登记册](risk-register.md)中的阶段 0 阻断风险已有 owner、验证计划和可接受 fallback。
- OpenAPI、迁移、UI 原型与测试 fixture 的阶段 1 输入已足够明确，不需要通过正式实现猜需求。

## 首个安全纵向切片出场条件

- 最小脚手架可在干净环境通过统一检查命令。
- 首个安全纵向切片和关键故障用例可自动复现。
- [风险登记册](risk-register.md)中的发布阻断风险已有验证结果、有效缓解或明确 No-Go 决策。
- 后续功能可以依据稳定 API、迁移、测试和容器基线逐项交付，而不需要重建核心边界。
