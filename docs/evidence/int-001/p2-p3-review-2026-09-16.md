## 发现

1. **高：标签审核冲突仍显示成功。** `AIReviewPage.tsx` 的 TagReviewPanel.submit 忽略响应 items 的 outcome，所有 resolved 请求都提示“审核已保存”并清空选择。OpenAPI 明确 HTTP 200 中每项可为 conflict；`ai.ts` 适配器也原样返回。P3 正式 HTTP 探针确实得到 conflict，但原浏览器测试未检查此分支。新增组件回归失败，实际发现“审核已保存。”元素。后端无错误写入不能替代前端正确反馈。待修复全冲突/混合结果、保留失败选择和刷新 revision，再验证真实浏览器并发修改场景。
2. **中：标签列表未接分页。** 适配器固定 limit=50 并支持 cursor，但 useAITagSuggestionsQuery 不接 cursor，TagReviewPanel 丢弃 nextCursor 且没有翻页入口。用户不能翻看第 51 条及以后的已接受/忽略记录，待审核列表也无法直接跨页选择。新增 nextCursor 非空的组件测试失败（无“下一页”按钮）。待接既有 URL/cursor/查询键和共享分页，并覆盖超过 50 条的真实数据。
3. **中：D03 三浏览器审核声明过宽。** p3-real.spec.ts 仅在 `info.project.name === "chromium"` 时实际选择并接受标签；Firefox/WebKit 只访问已变更后的页面并做 axe。三浏览器人物操作只有创建/刷新，非空归类/移出仍是 P2 Chromium 证据。原测试通过不证明三浏览器完整业务操作都通过。
4. **中：D04 不能称全矩阵关闭。** 真实设置矩阵只有 390/1280 两宽度，未覆盖 docs/ui-design.md 约定的 768/1265/1440 断点；键盘断言只证明 select 可聚焦、Tab 后非 BODY，不是完整操作路径。截图生成不等于视觉差异回归。人物/标签页面没有相同的双语言/主题/断点交叉矩阵，移动触控用例主要是 mocked viewer，不是正式后端 AI 审核触控验收。VoiceOver 仍按用户决定排除，不重新要求。
