## 1. 结论与优先级

- 状态：产品确认后的生产前端收敛方案
- 当前优先级：在继续扩展后台任务中心或系统维护功能前，先让现有生产 React 前端与
  [`prototypes/apple-redesign`](../prototypes/apple-redesign/index.html) 在布局、样式、
  交互层级和响应式行为上保持一致。
- 目标版本：MVP 现有已批准能力的 UI 收敛；不借此把未获准的 Post-MVP 功能带入生产。
- 视觉真相：原型 HTML、`styles.css`、唯一品牌资产和 `prototypes/apple-redesign/qa/`
  中已确认截图。生产页面不得自行“优化”为另一套视觉语言。
- 功能真相：`api/openapi.yaml`、生成 client、现有 capability 和已通过 Gate。原型状态不能
  反向发明 API 或把本地模拟功能伪装为生产能力。

这次不是只换颜色或套一层 CSS，而是按“共享基础 → 应用壳 → 页面模式 → 页面状态 → 同视口
视觉验收”的顺序重构。每完成一个页面，必须同时达到视觉一致、真实功能可用、响应式可用、
键盘可用和错误状态诚实，才可标记完成。

## 2. 已确认需求总表

以下内容合并了 2026-07-29～2026-07-30 的原型评审和本轮确认，不再分散依赖聊天记录。

### 2.1 全局 Header

1. 所有认证后的普通页面共用一条横跨完整视口的全局 Header。
2. 左侧使用 FolioPath 正式目录树 Logo 与字标；移动窄屏只保留 Logo 图形。
3. 中间是大尺寸全局搜索框，始终保持视觉居中，可在任意认证页直接提交并进入搜索页。
4. 搜索不再作为左侧菜单项；浏览侧栏只负责媒体库和目录。
5. 右侧是管理员入口。管理员菜单只保留“管理中心”和“退出登录”，不再同时重复“媒体库”
   和“设置”。
6. Header 在浏览、搜索、媒体库和设置页只有一份，不能出现页面 Header 与全局 Header 重复。

### 2.2 管理中心

1. 管理中心位于全局 Header 下方，桌面使用 216～280px 自适应左侧导航，内容占满剩余宽度。
2. 左侧导航采用单层结构，不再显示“内容与偏好 / 系统 / 账户”等稀疏分组标题。
3. 通用、媒体库、扫描与缓存、账户分别使用独立 URL 和独立页面；不使用同页锚点模拟。
4. 四个页面必须有真实、完整的功能状态，不允许只有静态控件：
   - 通用：主题、语言、默认布局和已批准的浏览偏好。
   - 媒体库：列表、创建、服务端批准目录选择、改名、扫描、取消、重试和安全移除。
   - 扫描与缓存：扫描计划、周期校验、每库扫描状态、缓存配额和已获合同支持的缓存操作。
   - 账户：管理员资料、密码修改和退出；密码修改只有在 OpenAPI 与后端 Gate 通过后接入生产。
5. `≤ 720px` 时左侧导航变为可横向浏览的分类条；页面内容全宽，不出现黑边或横向页面溢出。
6. 管理中心内容宽度随窗口自适应，不固定在狭窄居中列中。

### 2.3 浏览、当前目录筛选与预览

1. 浏览页桌面保留目录侧栏，主内容自适应；移动端改为抽屉。
2. 工具栏左侧集中放置“包含子目录”和“全部 / 图片 / 视频”三态。
3. 工具栏右侧依次放置当前目录关键字过滤、布局和排序；关键字只过滤当前目录中的子目录名和
   媒体文件名，不替代全局搜索。
4. 媒体类型不能作为孤立漏斗悬在面包屑右侧；高级筛选才进入弹层。
5. 当前目录、递归、关键字、媒体类型、布局与排序必须由统一 URL codec 恢复。
6. 右侧预览保持非模态：父列表仍可见、可滚动、可操作；完整查看器继续使用独立路由。
7. 页面只能有一个主要垂直滚动容器，修复向下滚动后的空白区、嵌套滚动和高度计算漂移。
8. 主内容、目录卡、媒体网格和右侧预览必须随窗口宽度自适应。

### 2.4 搜索

1. 全局 Header 提供随处可用的搜索入口；搜索页自身保留大搜索命令区和结果筛选。
2. 支持当前目录、当前媒体库和全部媒体库范围；查询、范围、类型、日期和排序写入 URL。
3. 搜索页不显示额外主菜单或重复侧栏。
4. 搜索结果复用浏览页唯一的媒体卡、虚拟集合和非模态预览，不创建第二套实现。
5. 无查询、无结果、离线、请求失败和已有结果继续加载失败是不同状态。

### 2.5 品牌、主题与响应式

1. 正式 Logo 用于认证页、欢迎页、全局 Header、favicon 和组件工作台，不使用文字占位。
2. 浅色、深色和跟随系统使用同一组中心 token 和同一主题机制。
3. 桌面、普通笔记本、平板和移动宽度都必须保持原型层级；不能只在 1440px 下看起来正确。
4. 390px 宽度不得产生页面级横向滚动；重要操作不能被折叠到不可发现的位置。
5. 所有主要交互保留可见焦点、DOM 顺序、键盘导航、Escape 关闭和焦点恢复。

### 2.6 运维与后续能力边界

1. 已完成的任务中心、任务详情和系统维护交互原型继续保留，作为后续产品和合同依据。
2. 任务中心属于 `Post-MVP/3` scope proposal；系统维护、完整性、应用数据备份和诊断包仍未
   排期。在 API、数据语义和后端 Gate 通过前，不接入生产菜单。
3. AI 语义搜索、人脸识别和 OCR 记录为上线后根据真实需求决定的 Future Candidate。
4. 三项智能能力当前不选模型、不引入向量数据库、GPU、外部服务或新部署单元。
5. 所有现在和未来的能力都必须保持原始媒体只读；删除、移动、重命名和修改原始文件永远不是
   管理页面的隐含能力。

## 4. 后端影响与合同缺口

界面还原不等于全部只改前端。当前 OpenAPI 已能支撑现有浏览、搜索、媒体库、扫描和设置主链，
但讨论中有三类真实新行为需要先补后端合同。

### 4.1 不需要后端调整

| 改动 | 原因 |
| --- | --- |
| 全局 Header、Logo、管理员菜单去重 | 纯共享壳、导航和样式调整 |
| 搜索页移除菜单、Header 提交全局搜索 | 已有 `GET /api/v1/assets?q=…` |
| 管理中心响应式布局与独立 URL | 页面和路由重组本身不改变服务端行为 |
| 主题、语言、网格/瀑布流等本机偏好 | 继续由现有前端偏好 owner 持久化 |
| 媒体库创建、列表、改名、安全移除 | 已有 library API |
| 扫描历史、开始、详情、取消和重试 | 已有 scan API；重试复用重新发起完整扫描 |
| 扫描周期和缓存配额 | 已有 `GET/PATCH /api/v1/settings` |
| 预览、查看器、滚动空白和自适应宽度 | 使用现有媒体合同，属于前端布局与生命周期修复 |

### 4.2 必须先调整后端

#### A. 账户资料与密码

当前认证合同只有 setup、login、session 和 logout，没有修改显示名称或密码的 operation。
`/settings/account` 要达到完整功能，需要：

- 接受管理员资料更新合同，至少支持显示名称；
- 接受修改密码合同，输入当前密码和新密码，服务端完成当前密码验证与 Argon2id 重算；
- 修改密码后保留当前会话、撤销其他会话；
- 加入 CSRF、限流、统一错误、幂等/并发语义和不记录秘密的安全测试；
- OpenAPI、auth service、SQLite adapter、HTTP handler、生成 client 与前端按 Gate 顺序交付。

在这组合同 Backend Ready 前，生产账户页只能展示当前会话和真实退出，不能放置假保存或假改密。

#### B. 当前目录关键字过滤

`GET /api/v1/libraries/{libraryId}/assets` 已支持 `directoryId + recursive + q`，所以媒体文件名过滤
可复用现有后端；但 `GET /api/v1/libraries/{libraryId}/directories` 当前没有 `q`。

如果只在浏览器里过滤已加载目录，会漏掉后续 cursor 页，不符合“过滤当前目录全部子目录”的
完整语义。推荐为目录列表增加规范化 `q`：

- 与 `parentId`、自然排序和 cursor query binding 组合；
- 只匹配可靠索引中的直接子目录名称，不扫描文件系统；
- 查询变化使旧 cursor 失败关闭；
- 离线时继续查询最后可靠目录索引；
- 更新 OpenAPI、SQLite 查询、集成测试、生成 client 和统一 Browse URL codec。

如果产品选择“只过滤当前已加载项”，可以不改后端，但页面必须明确标注该限制；本方案不推荐
这种降级。

#### C. 缓存状态、清理与重建

当前设置合同只有缩略图缓存配额，没有缓存使用量、补齐缺失、清理或全部重建 operation。
若 `/settings/storage` 要实现原型中的完整缓存操作，需要后端提供：

- 可安全展示的缓存使用量、水位和最近清理摘要；
- “清理可重建缓存”或等价的有界 operation；
- 若进入范围，“补齐缺失”和“全部重建”的批次创建、确认、进度、取消、重试和失败语义；
- 任务重启安全、幂等、资源上限、磁盘安全余量和原始媒体只读证据。

“补齐缺失 / 全部重建 / 统一任务详情”属于 `FTR-OPS-001`，继续由 `Post-MVP/3` Gate 管理；
不能为了匹配原型提前塞进 MVP API。MVP 本轮可以先完成扫描计划、扫描状态和缓存配额的独立页面。

### 4.3 后端仍保持阻断的后续功能

- 任务中心统一高层任务投影；
- 系统健康、完整性报告、应用数据备份和诊断包；
- AI 语义搜索、OCR 和人脸识别。

这些能力不仅需要接口，还涉及任务状态、数据 schema、资源、隐私、备份恢复或信任边界，
必须分别完成 Change Record、OpenAPI/data contract 和 Backend Evidence Ready。

## 5. 怎么改

### 5.1 冻结视觉真相

1. 为每个原型页面登记目标 URL、语言、主题、视口、展开状态和数据状态。
2. 固定首批比较视口：
   - `1440 × 900`：宽桌面主验收；
   - `1265 × 800`：普通笔记本与管理中心自适应；
   - `768 × 1024`：平板与导航转换；
   - `390 × 844`：移动端和横向溢出验收。
3. 动态内容使用确定性合成媒体与契约 fixture；截图比较时只遮罩时间戳、进度时间等真正动态
   区域，不遮罩布局问题。
4. 原型调整后必须先更新参考截图与变更记录，不能让生产代码自行成为新的视觉真相。

### 5.2 建立唯一 token 与共享组件映射

将 `prototypes/apple-redesign/styles.css` 中已确认值映射到生产中心 token，而不是把原型 CSS
整份复制进 feature：

| 原型概念 | 生产唯一 owner |
| --- | --- |
| 背景、表面、文字、分隔线、强调色、状态色 | `web/src/styles/themes.css` |
| 字号、行高、间距、圆角、阴影、层级、动效 | `web/src/styles/tokens.css` |
| Logo | `BrandMark` |
| 按钮、图标按钮、输入、选择、对话框、菜单、Toast | `web/src/components/ui` |
| 全局 Header、管理中心壳、浏览壳 | `web/src/components/patterns` |
| 媒体集合、预览、查看器 | 现有唯一 `MediaCollection`、`MediaPreview`、`MediaViewer` |

先改共享 owner，再由页面组合。禁止在 Browse、Search、Libraries、Settings 中分别写一套相同
Header、按钮、卡片、菜单或响应式规则。

### 5.3 重构应用壳

1. `AppShell` 调整为“全局 Header + 页面级 Body”，Header 不再被左侧栏截断。
2. Header 使用三轨网格：左右轨道等宽，中间搜索限制最大宽度，保证视觉居中。
3. 将目录侧栏和管理中心导航做成两个明确的页面模式：
   - `BrowseShell`：媒体库切换器 + 目录树；
   - `ManagementShell`：通用 + 媒体库 + 扫描与缓存 + 账户。
4. Search 不挂载侧栏；Viewer 使用独立深色 chrome，但保留统一认证与返回上下文。
5. 账户菜单只负责跨任务入口，不复制管理中心内部导航。
6. 桌面 Header 固定，页面只保留一个内容滚动上下文；移动侧栏使用抽屉和 scrim。

### 5.4 逐页还原并保留真实功能

按以下顺序实施，每一步都可单独回归：

1. 认证与公共页：Logo、表单、错误和移动排版。
2. 全局 Header 与账户菜单。
3. 管理中心壳与媒体库页。
4. 通用、扫描与缓存、账户独立路由。
5. 浏览页目录侧栏、面包屑、工具栏、当前目录过滤和滚动高度。
6. 媒体网格、非模态预览和完整查看器。
7. 搜索命令区、筛选、结果和预览。
8. 所有加载、空、离线、失败、冲突、取消、处理中和成功状态。

页面组件只负责组合；查询、URL、错误映射和提交继续由现有单一 owner 管理。若原型展示了生产
合同尚未支持的操作，页面应明确阻断并记录 Backend Ready 依赖，不能用 localStorage 或假成功
补齐。

### 5.5 拆分管理页面

1. `/settings/general` 只保留主题、语言、网格/瀑布流默认值和固定预览偏好。
2. `/settings/libraries` 复用现有真实媒体库和扫描 API，不改变原媒体安全语义。
3. `/settings/storage` 复用现有扫描周期、缓存配额和扫描状态能力；清理/重建按钮只在已有
   operation 合同存在时启用。
4. `/settings/account` 先接会话信息和真实退出；资料和密码修改按 `FR-AUTH-005` 先完成
   OpenAPI、安全评审、后端实现与 Backend Ready，再接前端。
5. 新建媒体库与扫描详情保留独立可直达页面，并在管理中心导航中保持媒体库或扫描分类选中。

## 6. 怎么保证一致性

### 6.1 设计一致性 Gate

每个页面必须保存同一视口、同一状态的“原型截图 + 生产截图”组合比较证据。验收条件：

- P0、P1、P2 视觉差异为零；P3 只能作为明确的后续细节记录。
- 主要区域边界、Header 高度、侧栏宽度、内容 padding、控件高度和卡片间距偏差不超过 2px。
- 标题和正文换行位置一致；字体家族、字号、字重、行高和字距使用同一 token。
- 颜色来自同一语义 token；不允许 feature 内出现第二组裸色值。
- Logo、缩略图和非标准资产使用正式资产，不用 CSS 图形、emoji 或文字占位。
- 1440、1265、768、390 四档均无被遮挡的主要操作和页面级横向溢出。
- 浏览页滚到顶部、列表中段和底部都不出现多余空白区；预览开关前后布局稳定。

### 6.2 自动化防漂移

1. 扩展 `web/tests/e2e/visual-regression.spec.ts`，为全局 Header、管理中心、浏览、搜索和
   查看器建立 Linux-owned 稳定截图。
2. 共享组件在 Storybook 固定浅色/深色、中英文、默认/hover/focus/disabled/error 状态。
3. token、共享组件或壳变更必须更新所有受影响基线；feature PR 不能无解释批量接受截图变化。
4. 为以下结构增加组件测试：
   - 页面只有一个全局 Header；
   - 管理员菜单不重复管理模块；
   - Search 无侧栏；
   - 管理中心四条独立路由；
   - 390px 无页面级横向溢出；
   - Escape 关闭菜单/抽屉并恢复焦点。
5. 每页执行真实浏览器主流程，不以 build、HTTP 200 或静态截图代替交互验证。

### 6.3 功能一致性 Gate

- 页面成功、冲突、认证失败、离线、取消和重试必须来自真实 API 或评审后的 fixture。
- 导航、搜索、范围、筛选、排序和返回上下文必须通过 URL 恢复。
- 不直接 `fetch`，只通过生成 client 和领域 adapter。
- 不复制 Query key、URL codec、API error mapper、提交防重或媒体预览 controller。
- 生产管理页的按钮必须完成操作或明确禁用并说明合同依赖，不能出现点击无反应。

### 6.4 可访问性与质量 Gate

每个完成批次至少执行：

```sh
make fmt
make arch-check
make generate-check
make lint
make test
make test-integration
make test-e2e
```

若某个目标不存在或环境无法执行，交付记录必须明确说明，不能写成“已通过”。前端还需执行
typecheck、Storybook/a11y、Chromium/Firefox/WebKit、键盘、触摸和四档响应式检查。

## 7. 分批交付与验收顺序

### Batch A：共享基础与壳

- token 映射；
- GlobalHeader、AccountMenu；
- BrowseShell、ManagementShell；
- 四档响应式；
- 单 Header 和菜单去重测试。

出口：认证后的所有页面先拥有正确的共同骨架，页面功能不回退。

### Batch B：管理中心

- 媒体库页视觉还原；
- 通用、扫描与缓存、账户独立路由；
- 新建、改名、扫描、取消、重试、移除、设置保存真实流程；
- 未 Backend Ready 的账户操作保持阻断。

出口：每个菜单都是可直达的独立功能页，刷新和前进后退保持当前页。

### Batch C：浏览、搜索与预览

- 当前目录过滤和右侧工具组；
- 自适应媒体网格和无空白滚动；
- 搜索无侧栏与全局搜索；
- 非模态预览和完整查看器视觉对齐。

出口：核心找图、浏览和查看路径在四档视口通过视觉与功能 Gate。

### Batch D：状态矩阵与发布回归

- 中英文、浅色/深色；
- 加载、空、离线、失败、冲突、取消、处理中；
- 三浏览器、键盘、触摸、axe；
- 完整同视口截图对照和 Stage 5 回归。

出口：所有已批准生产页面满足本方案 Definition of Done。

## 8. 每页 Definition of Done

只有同时满足以下条件才可勾选页面完成：

1. 已关联原型编号、生产路由和后端 Gate。
2. 正常、空、加载、错误和恢复状态均有实现或明确不适用。
3. 核心按钮、菜单、输入、筛选和导航实际可用。
4. 1440、1265、768、390 同状态视觉比较无 P0/P1/P2。
5. 浅色/深色、中英文没有截断或层级漂移。
6. 键盘、焦点、Escape、读屏名称和 reduced-motion 通过。
7. 单元/组件/E2E/视觉回归已执行并记录。
8. 没有新增原始媒体写入、绝对路径泄露、假 API、重复 owner 或未授权生产 feature。

## 9. 明确不在本轮顺带实现

- 任务中心和系统维护的生产 API/UI；
- 完整性检查、应用数据备份、恢复和诊断包生产能力；
- AI 语义搜索、人脸识别和 OCR；
- 多用户、角色、上传、转码、回收站或新部署单元；
- 为了“看起来完整”而用 mock 或 localStorage 替代缺失后端合同。

这些内容继续保留在各自 feature/Change Record 中，后续按需求证据和 Gate 单独启动。
