# FolioPath 产品需求文档

## 文档状态

本文是首个可用版本（MVP）的已确认产品基线，不表示下述功能已经发布。用户已于 2026-07-23 确认 [RQ-001～RQ-014](requirements-checklist.md) 全部采用 A，并于 2026-07-28 通过 [CR-2026-002](changes/CR-2026-002-authenticated-lan-http.md) 确认受信局域网 HTTP 部署；实现与验收必须按这些选择执行。当前范围由 [`MVP-2026-07-23` scope manifest revision 4](releases/MVP-2026-07-23-scope-r4.md) 锁定，新用户能力默认进入后续版本；改变范围必须遵守[交付与架构治理](architecture/delivery-governance.md)的 Change Record、影响分析和 scope trade-off，不能靠不断追加 FR 延后发布。

## 产品愿景

FolioPath 是一个以真实文件夹结构为核心的自托管图片与视频浏览器。用户只需把一个足够大的媒体根目录以只读方式挂载到容器，再在 Web 设置中创建多个媒体库，即可通过目录树、递归视图和媒体查看器浏览现有收藏，而不必导入、复制或重组文件。

首版要解决的核心问题是：现有媒体已经按目录整理，但常见照片应用弱化了目录层级，而文件管理器又缺少适合大量图片与视频的缩略图、连续浏览和跨子目录视图。

## 目标用户与 JTBD

这里的“管理员”和“浏览者”是使用场景，不代表多用户权限角色；MVP 由同一个单管理员账号完成设置和浏览。

| 用户 | 场景 | Job to be done |
| --- | --- | --- |
| NAS／家庭服务器管理员 | 已有一个或多个照片目录，希望低成本提供 Web 浏览 | 当我部署服务时，只配置媒体根目录和数据目录，之后在界面内完成媒体库管理 |
| 按文件夹整理媒体的个人用户 | 年份、地点、项目等层级已经有意义 | 当我寻找内容时，沿原目录逐级浏览，而不是重新建立应用内相册 |
| 大型素材收藏的浏览者 | 一个目录下可能有很多子目录和媒体 | 当我想连续查看一个主题时，开启递归模式浏览全部后代，同时知道每项来自哪里 |
| 低维护成本的自托管用户 | 挂载可能临时离线，扫描可能中断 | 当基础设施发生短暂故障时，应用保留已有索引并明确提示，而不是误判为空并清除数据 |

## 产品原则

1. **Folder first**：目录树、面包屑和媒体库内相对路径是主要信息架构。
2. **Non-destructive**：原始媒体始终只读；任何应用操作都不得移动、重命名、修改或删除它。
3. **Filesystem as truth**：文件系统决定媒体存在与层级；SQLite、搜索索引和缩略图均为派生状态。
4. **Simple deployment**：一个容器、一个端口、一个媒体根挂载和一个数据挂载；业务设置尽量在 Web 界面完成。
5. **Safe degradation**：离线、权限错误、损坏媒体和中断扫描必须可见且可恢复，不能破坏已有索引。
6. **Bounded performance**：大型目录使用增量扫描、游标分页、虚拟化和有界后台任务，不以无界内存或并发换取速度。
7. **Cross-platform web UI**：视觉服务于媒体内容；桌面与移动浏览器均须有清晰、可访问的操作方式。

## MVP 范围

MVP 包含：

- 单容器部署，以及固定的只读 `/library` 与可写 `/app/data` 边界。
- 在 Web 设置中创建、查看状态、重新扫描和移除多个媒体库。
- 由服务端批准的 `/library` 子目录选择器、递归扫描和安全路径校验。
- 保留真实层级的目录树、面包屑、当前目录视图和递归后代视图。
- JPEG、PNG、WebP、GIF 缩略图，MP4、MOV、MKV 视频封面，响应式媒体画廊、图片查看器和浏览器兼容编码的直接播放。
- 文件名、路径、类型和文件修改时间维度的搜索、过滤与排序；当前媒体库为默认范围，可切换当前目录（可递归）与全部媒体库。
- 扫描进度、离线、失败、部分不可读、损坏媒体和不支持播放等状态反馈。
- 明暗主题、键盘操作、焦点可见、减少动态效果和响应式布局。
- 创建后、应用启动、手动和定时完整校准扫描；定时扫描默认每 24 小时，可在 UI 修改或关闭。
- 首个稳定版的首次设置单管理员账号、会话和退出登录；认证完成后支持受信局域网 HTTP
  直连，公网 TLS 与反向代理由部署者按需提供。
- 简体中文和英文界面，默认跟随浏览器并可在设置中切换。

## 明确非目标

MVP 不包含（稳定 ID 由 [scope manifest](releases/MVP-2026-07-23-scope.md) 固定）：

- `MVP-NG-001`：上传、移动、重命名、删除、整理或备份原始媒体。
- `MVP-NG-002`：应用内相册替代真实文件夹层级。
- `MVP-NG-003`：视频转码、自动生成兼容播放版本或流媒体自适应码率。
- `MVP-NG-004`：AI 分类、人脸识别、对象识别、语义搜索或重复文件检测。
- `MVP-NG-005`：RAW 工作流、图片编辑、完整 EXIF 编辑器或完整媒体信息面板。
- `MVP-NG-006`：分享链接、收藏、评分、评论、地图、时间线或浏览历史。
- `MVP-NG-007`：多实例共享写入、水平扩展、外部数据库或独立任务服务。
- `MVP-NG-008`：依赖文件系统 watcher 保证索引正确性；watcher 仅可作为未来优化。

## 功能需求

### 部署与设置

| ID | 需求 |
| --- | --- |
| FR-DEP-001 | 系统必须以单个 FolioPath 容器和单个 HTTP 端口运行，媒体根目录固定为 `/library`，持久数据目录固定为 `/app/data`。 |
| FR-DEP-002 | 推荐部署必须支持仅用 `/host/media:/library:ro` 与 `/host/data:/app/data` 两个 bind mount 开始使用；Docker 自动创建 root-owned 数据目录时不得要求额外 `chown`、named volume 或 Compose `user`。 |
| FR-DEP-003 | 除宿主机挂载、网络和运行环境等容器边界外，媒体库及面向用户的应用设置必须通过 Web 界面管理并持久化。 |
| FR-DEP-004 | 应用必须明确显示其处于规划、初始化、可用或需要处理的状态，不能把未完成初始化表现为空媒体库。 |
| FR-DEP-005 | 推荐 Compose 必须可通过单个宿主端口直接提供受单管理员认证保护的局域网 HTTP 访问；公网或其他不可信网络的 TLS 终止与反向代理由部署者负责，不是 FolioPath 的必需部署单元。 |

### 认证与会话

| ID | 需求 |
| --- | --- |
| FR-AUTH-001 | 首个稳定版必须提供无默认密码的首次单管理员初始化、登录、会话状态、退出登录和会话过期处理。 |
| FR-AUTH-002 | 初始化完成后不得再次开放匿名创建管理员；所有媒体、媒体库、扫描、搜索和设置接口必须要求有效身份。 |
| FR-AUTH-003 | 开发预览版在认证完成前只能绑定回环地址或置于可信认证反向代理后，不支持直接公网暴露或无认证局域网模式。 |
| FR-AUTH-004 | 会话必须使用安全 Cookie、过期与撤销机制，并为所有状态修改提供 CSRF 防护或等价的同源保护。 |
| FR-AUTH-005 | 唯一管理员必须能在账户页修改显示名称和密码；修改密码要求当前密码、新密码与确认密码，新密码至少 8 个 Unicode 字符。成功后当前会话继续有效，其他会话必须重新认证。 |

### 媒体库管理

| ID | 需求 |
| --- | --- |
| FR-LIB-001 | 用户必须能在设置中新建多个具备名称和根目录的媒体库，无需为 `/library` 内的新媒体库修改 Compose 或重启容器。 |
| FR-LIB-002 | 目录选择器只能选择 `/library` 本身或服务端批准的后代目录；管理 API 使用相对于 `/library` 的规范路径，空值表示根本身，不接受任意宿主机或容器绝对路径。 |
| FR-LIB-003 | 媒体库默认包含所选根目录的全部后代，并保留原始目录层级。 |
| FR-LIB-004 | 创建或修改媒体库时必须拒绝相同、祖先或后代关系的重叠根目录，并给出可理解且不泄露宿主机路径的错误。 |
| FR-LIB-005 | 管理 UI/API 可显示媒体库根的 allowed-root-relative 值和安全容器显示路径；媒体内容 API 只传递 ID 或 library-relative 路径。任何接口都不得暴露宿主机路径。 |
| FR-LIB-006 | 根目录不存在或不可读时，系统必须将媒体库标记为离线，保留已有索引，并提供重新检查或扫描入口。 |
| FR-LIB-007 | 移除媒体库必须仅删除配置、索引、任务和派生缓存；确认界面必须明确说明原始文件不会被修改。 |
| FR-LIB-008 | 媒体库名称必须非空且在实例内唯一，并允许改名；MVP 不允许原地修改根路径，更换路径需移除后重新创建。 |

### 扫描与索引

| ID | 需求 |
| --- | --- |
| FR-SCN-001 | 系统必须在首次创建媒体库后安排完整扫描，并支持启动校准、手动扫描与定时完整扫描。 |
| FR-SCN-002 | 扫描必须流式遍历并使用全局有界队列；不得把完整目录树读入内存或为每个条目启动无界任务。 |
| FR-SCN-003 | UI 必须显示每个媒体库最近扫描状态、开始／结束时间、可用进度、结果统计和经过净化的错误摘要。 |
| FR-SCN-004 | 只有一次完整扫描全部成功后才能清理旧代次记录；失败、取消、中断、离线或任一子树不可可靠读取时必须保留旧索引。 |
| FR-SCN-005 | 同一媒体库同时最多运行一次完整扫描；重复请求必须合并、拒绝或安全排队，而不能并行破坏状态。 |
| FR-SCN-006 | 进程重启后扫描和派生媒体任务必须能安全恢复或重试，不得把半成品标记为可用。 |
| FR-SCN-007 | 创建媒体库后立即扫描，应用启动时执行校准，并默认每 24 小时执行完整扫描；管理员可在 UI 修改周期或关闭定时扫描。 |
| FR-SCN-008 | 扫描详情必须提供协作式取消；取消后保留上次可靠索引和本次已安全提交的新增记录，并提示需要重新完整扫描。 |
| FR-SCN-009 | 扫描普通项和隐藏项，但默认跳过维护清单中的系统派生目录和回收站；UI 必须显示跳过统计。 |

### 导航与浏览

| ID | 需求 |
| --- | --- |
| FR-BRW-001 | 用户必须能切换媒体库，并通过可折叠目录树和面包屑进入任意已索引目录。 |
| FR-BRW-002 | 默认目录视图只显示当前目录的媒体；用户必须能开启递归模式查看当前目录及全部后代媒体。 |
| FR-BRW-003 | 递归结果中的每项必须保留并显示其来源相对路径，并能导航回来源目录。 |
| FR-BRW-004 | 媒体库、目录、递归开关、搜索、过滤和排序等可导航状态必须编码在 URL 中，以支持刷新、前进后退和复制链接；浏览过滤必须提供“全部、图片（含 GIF 动图）、视频”三态。 |
| FR-BRW-005 | 列表必须使用稳定游标分页和虚拟化渲染，不得一次请求或渲染完整大型集合。 |
| FR-BRW-006 | 画廊必须提供自适应网格和瀑布流能力；自适应网格是默认布局，瀑布流为可记忆的切换选项。 |
| FR-BRW-007 | 加载中、空目录、无搜索结果、离线、索引陈旧和读取失败必须使用不同状态表达，并提供适合该状态的下一步操作。 |
| FR-BRW-008 | 目录树必须忠实显示所有可读取目录，包括没有受支持媒体的目录，并在可用时显示直接与递归媒体计数。 |
| FR-BRW-009 | 普通目录默认按自然文件名升序，递归和搜索默认按文件修改时间倒序；显式按名称排序时必须先按来源文件夹分组，再在文件夹内按自然文件名排序；改变排序必须重置游标。 |
| FR-BRW-010 | 浏览页必须提供当前目录关键字过滤，并对当前目录的全部直接子目录和符合当前 recursive 范围的媒体生效；目录与媒体查询均使用可靠索引、稳定 cursor 和统一 URL 状态，不能只过滤客户端已加载页。 |

### 搜索、过滤与排序

| ID | 需求 |
| --- | --- |
| FR-SRH-001 | 系统必须支持按文件名和媒体库内相对路径搜索，并以索引查询响应，不能在请求期间递归遍历文件系统。 |
| FR-SRH-002 | 用户必须能按图片、动画图片和视频类型过滤，并按名称与已确认的日期字段排序。 |
| FR-SRH-003 | 搜索结果必须显示所在媒体库与来源相对路径，并可跳转到来源目录或打开查看器。 |
| FR-SRH-004 | 搜索范围、排序、过滤与分页游标必须具有稳定且可恢复的 URL 语义；默认搜索当前媒体库，并允许切换当前目录（可递归）与全部媒体库。 |

### 缩略图与媒体查看

| ID | 需求 |
| --- | --- |
| FR-MED-001 | 系统必须为受支持图片生成合适尺寸的缩略图，为受支持视频抽取封面；失败项必须有占位和可诊断状态。 |
| FR-MED-002 | 缩略图和封面是可重建缓存，必须按源指纹与变换版本失效，并以临时文件加原子替换方式落盘。 |
| FR-MED-003 | 浏览和搜索中的媒体点击默认使用不遮挡父列表的非模态预览；未固定时单击其他媒体切换预览，固定后单击只选择、双击才切换预览。完整图片查看器作为显式操作和可直达路由，必须支持适应视口、缩放和平移、1:1、前后浏览、全屏，以及关闭后恢复触发位置与焦点。窄屏预览进入内容流，不使用遮罩阻断父页面。详见 [CR-2026-001](changes/CR-2026-001-non-modal-media-preview.md)。 |
| FR-MED-004 | 视频必须先由当前浏览器通过原文件、条件请求和 HTTP Range 尝试直接播放；服务端不得用保守 codec 白名单预先阻断，MVP 不得自动转码。 |
| FR-MED-005 | 对可索引但当前浏览器实际播放失败的媒体，UI 必须显示封面、基本状态和明确原因，不能假装播放成功。 |
| FR-MED-006 | 图片索引与缩略图支持 JPEG、PNG、WebP、GIF；视频索引与封面支持 MP4、MOV、MKV。只有浏览器原生兼容的编码直接播放；SVG、HEIC/HEIF、AVIF 与 RAW 不属于 MVP 承诺。 |
| FR-MED-007 | 查看器显示文件名、相对路径、类型、尺寸或时长和修改时间；MVP 不提供完整 EXIF 面板、显式下载按钮或移动端滑动切换。 |
| FR-MED-008 | 缩略图缓存默认配额为 10 GiB，可在 UI 修改；达到水位后按最近最少使用清理可重建缓存，并保留安全磁盘余量。 |

### 界面与可访问性

| ID | 需求 |
| --- | --- |
| FR-UI-001 | UI 必须在桌面和移动宽度下提供完整的浏览、搜索、查看和媒体库状态访问能力。 |
| FR-UI-002 | 所有核心操作必须使用语义控件，可由键盘完成，并保持可见焦点与符合 DOM 顺序的导航。 |
| FR-UI-003 | 缩略图、查看器与状态信息必须提供有意义的替代文本或可访问名称；颜色不能是唯一的状态表达。 |
| FR-UI-004 | UI 必须支持浅色、深色和跟随系统主题，并尊重减少动态效果、对比度与透明度偏好。 |
| FR-UI-005 | 动效必须可打断、保持空间关系且不妨碍滚动；不得为每个虚拟化缩略图增加高成本动画。 |
| FR-UI-006 | 界面必须提供简体中文和英文，默认跟随浏览器语言，并允许在设置中切换。 |
| FR-UI-007 | 桌面使用固定目录侧栏，移动端使用目录抽屉；视觉采用中性内容优先基调，只在查看器、抽屉和直接操作中使用克制动效。 |
| FR-UI-009 | 管理中心必须提供配置、媒体库、账户、系统日志和关于五个可直达分类；配置使用通用/扫描/缓存页签，媒体库使用媒体库/扫描记录/处理结果页签。URL 必须保留当前分类和页签，各页负责自己的保存、校验、处理中、成功、失败和危险操作状态。 |

## MVP 验收标准

候选版本只有在以下端到端场景均通过后，才可称为 MVP：

1. `MVP-AC-001`：使用一个只读媒体根挂载和一个数据挂载启动服务，完成单管理员初始化，并在不改 Compose 的情况下从 UI 创建至少两个互不重叠的媒体库。
2. `MVP-AC-002`：对重叠根目录、越界路径和符号链接逃逸给出安全错误；整个流程没有宿主机路径泄露或原文件写入。
3. `MVP-AC-003`：完整扫描后可用目录树、面包屑、当前目录与递归模式浏览合成测试库；重启后索引、设置和任务状态保持一致。
4. `MVP-AC-004`：扫描中断、子目录权限失败和根目录离线都保留旧索引；只有后续完整成功扫描才清理已消失项目。
5. `MVP-AC-005`：大型合成数据集使用稳定游标和虚拟化浏览，不出现一次性全量请求、全量 DOM 渲染或无界任务增长。
6. `MVP-AC-006`：受支持图片可显示缩略图并在查看器打开；受支持视频可通过 Range 请求定位播放；损坏或不兼容媒体显示安全的降级状态。
7. `MVP-AC-007`：关键流程可仅用键盘完成，移动宽度可访问目录、搜索、设置和查看器，并正确响应减少动效设置。
8. `MVP-AC-008`：媒体库移除后其应用数据和派生缓存被清理，原始目录及内容逐字节保持不变。

## 成功判断

MVP 的产品成功首先以“低配置成本、目录语义正确、原文件安全、故障可恢复”判断，而不是以功能数量判断。内测应记录：从启动到首次可浏览所需操作、扫描成功／失败原因、离线恢复结果、缓存占用、列表响应与滚动体验。目标档已固定为约 10 万媒体、1 万目录、4 GiB 内存的四核环境；具体延迟和吞吐门槛在可重复 spike 后写入性能测试，不在当前规划稿中虚构数值。

## 假设与依赖

- 部署者能够把合法拥有或有权访问的媒体以只读方式挂载到 `/library`，并为 `/app/data` 提供可写、本地且可靠的文件系统。
- 单个 FolioPath 实例独占其 SQLite 数据库，不支持多个实例共享写入。
- 镜像可提供匹配目标架构的 libvips、`ffprobe` 和 FFmpeg；具体格式支持受构建依赖和浏览器解码能力共同限制。
- 首次大型扫描可能耗时；可浏览性与资源目标取决于 [RQ-011](requirements-checklist.md#rq-011首版容量目标) 的数据规模选择。
- 未实现内建认证的开发预览版只能使用本机回环地址或可信认证反向代理，且不得直接暴露到互联网；稳定版必须具备内建单管理员认证。
- OpenAPI、数据模型、路径安全和扫描代次语义分别受当前权威 `api/openapi.yaml`、[数据模型](data-model.md)、[安全模型](security.md) 与 [ADR-0003](adr/0003-scan-consistency.md) 约束。
