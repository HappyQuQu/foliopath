## 结论

完整方向在保持单容器、原媒体只读和本地处理的前提下存在以下四项可独立能力：

1. 图片自然语言语义搜索；
2. 从受控词表生成 AI 标签建议，由用户确认后才写入手动标签；
3. 用既有视频故事板代表帧做近似内容搜索；
4. 后台检测人脸并先做匿名聚类，用户再建立人物、命名、合并、拆分或把单个人脸归入人物。

revision 2 已冻结上述四项及模型基础，S2A/S2B/S2C 的 fail-closed production 后端均已 Backend Ready。
这不等于已经具备发布条件：reviewed catalog 保持为空，face runtime/route 不进入 app composition；真实质量、
隐私、native 双架构、4 GiB 最终模型联合负载和模型再分发统一由 S4 Release Gate 持有。

## 产品问题与目标用户

FolioPath 的主要内容是以人物为主的套图集。目录仍是套图和来源结构的事实来源；AI 的价值是
在跨套图浏览时增加“看起来像什么”和“画面中是谁”两种派生入口，而不是重新组织原文件。

目标：

- 用户能用中文或英文描述画面，在当前库、当前目录或全部库中找到视觉相关图片和视频；
- 用户能看到有限、可解释、可撤销的标签建议，不让模型污染人工标签；
- 程序先把相似人脸归为匿名组，用户只需给有价值的组建人物库；
- 已命名人物可吸收一个匿名组，也可吸收单张图片中的某个人脸；
- 所有模型结果都可重建，任何失败都不影响目录浏览、普通搜索和原媒体。

## 需求

### 语义检索

- `FR-INT-001`：管理员可按媒体库启用或停用智能分析；默认关闭。
- `FR-INT-002`：系统为图片生成版本化视觉 embedding，并支持中文、英文文本查询。
- `FR-INT-003`：语义查询可组合媒体库、目录、递归范围和媒体类型筛选；不得替代现有字面搜索。
- `FR-INT-004`：视频复用已经生成的 4/10 格故事板帧，按最相关代表帧返回视频及匹配帧信息。
- `FR-INT-005`：模型升级或索引损坏时可后台重建；最后可靠结果继续可用，不能先删后建。

### AI 标签建议

- `FR-INT-006`：系统只从管理员维护的受控词表或已有标签中计算建议和置信度。
- `FR-INT-007`：建议与人工标签严格分离；只有用户确认后才通过既有 curation owner 写入标签。
- `FR-INT-008`：用户可忽略单条建议；首版不以忽略结果在线训练模型。

### 人脸聚类与人物库

- `FR-INT-009`：后台对图片检测人脸、生成 embedding，并将相似人脸形成匿名聚类。
- `FR-INT-010`：用户可从匿名聚类创建人物并自行命名；名称不是模型预测。
- `FR-INT-011`：用户可将匿名聚类合并到已有或新人物，也可合并、拆分、移动或排除错误成员。
- `FR-INT-012`：用户可把单张图片中的指定人脸归入已有人物；一张多人图片按 face ID 操作，
  不能把整张图片隐式归给一个人物。
- `FR-INT-013`：人工归类、排除和拆分形成约束，后续聚类不得静默覆盖；已命名人物之间不得自动合并。
- `FR-INT-014`：用户可删除某库的全部人脸派生数据和人物关系；删除永不触碰原媒体。

### 状态与运维

- `FR-INT-015`：界面显示模型是否可用、处理进度、失败原因、索引版本和重建状态。
- `FR-INT-016`：媒体库 offline、模型缺失、任务取消或部分失败时保留最后可靠索引。

### 模型获取与存储

- `FR-INT-017`：revision 1 只接受产品内建兼容清单声明的离线模型包；启用前完成用途、版本、架构、
  许可证标识、大小、文件清单和 SHA-256 校验。在线获取保留为未来 scope，不属于本合同。
- `FR-INT-018`：系统可扫描固定只读容器目录 `/models`，区分已安装、可用和不兼容文件；不接受
  UI 提交宿主机路径，也不加载兼容清单以外的任意 ONNX 或其他模型。
- `FR-INT-019`：管理员可把已验证包复制到 `/app/data/models` 托管，或在明确风险后从只读
  `/models` 直接使用。复制托管是默认方式；两种方式都不得修改映射源文件。
- `FR-INT-020`：管理员可选择已安装且兼容的模型版本。模型变更必须创建新 generation、后台重建
  并验证后再激活；旧模型和最后可靠索引在切换成功前继续服务。

### 非功能要求

- `NFR-INT-001`：全部推理默认本地完成，不上传媒体、裁剪、人脸向量或查询文本。
- `NFR-INT-002`：智能任务有界、可取消、可恢复，优先级低于浏览所需的 poster/thumbnail。
- `NFR-INT-003`：禁用时不启动模型、不扫描媒体、不保留该库的新派生结果。
- `NFR-INT-004`：模型、输入变换、输出 schema 和索引格式均有 generation，不能跨代混用。
- `NFR-INT-005`：公开 API 不返回原始 embedding，不接受绝对路径或任意模型 URL。
- `NFR-INT-006`：在 4 CPU、4 GiB、10 万媒体目标档满足经 S0 冻结的资源和延迟门槛。
- `NFR-INT-007`：模型包一律视为不可信输入；只有内建 allowlist/manifest 与哈希完全匹配的纯权重
  文件可进入运行时，模型附带代码、插件、动态库和脚本永不执行。首个发布切片的 ONNX graph 必须
  内嵌全部 initializer，external-data 不受支持；发行校验拒绝引用，运行时再以固定 size/hash 约束图。
- `NFR-INT-008`：公开 API 不接受下载 URL、绝对路径或任意模型 ID；只接受服务端本轮扫描签发的
  opaque candidate ID，响应和日志不得泄露宿主机路径或模型内部位置。
- `NFR-INT-009`：直接使用的 `/models` 文件缺失、变更或变为可写时必须失败关闭并把模型标记为
  unavailable；保留最后可靠派生索引和人工状态，普通浏览/字面搜索继续可用。
- `NFR-INT-010`：模型扫描、复制、校验和激活只能由已认证管理员明确触发，使用有界临时空间、
  超时、并发 1、磁盘安全余量、临时文件和校验后原子发布；revision 1 不主动联网。

## 明确不做

- 不自动识别或推测具体 Coser、模特、公众人物、真实身份或动漫角色姓名。
- 不根据服装、妆容、作品目录或网络资料猜测人物身份。
- 不做人脸登录、监控、年龄/性别/种族/情绪等敏感属性推断。
- 首版不做人脸视频追踪；视频仅参与代表帧语义搜索。
- 不做 OCR、自由生成式描述、内容审核、NSFW 分类、以图生图或图片编辑。
- 不自动接受 AI 标签，不自动合并两个已命名人物。
- 不接入云端推理、外部人物库、任意模型市场、任意下载 URL 或独立 AI 服务。
- 不承诺动作时序、对白、声音、字幕或视频精确时间段的语义理解。

## 用户流程

### 图片语义搜索（revision 1）

1. 管理员为媒体库启用智能分析并看到模型/空间预计值。
2. 后台按有界批次生成图片 embedding；视频不进入本 revision。
3. 用户在搜索页明确选择“文件名”或“画面语义”，输入中文或英文描述。
4. 结果按相似度排序，并保留库、目录和图片类型筛选。
5. 索引不完整时界面显示覆盖率，不把“未处理”误报为“无结果”。

查询文本不得包含 tokenizer 注册控制字符串 `</s>` 或 `<unk>`（大小写不敏感）；服务端在推理前以
普通无回显校验错误拒绝，不能把它们作为模型控制 token 执行。

### AI 标签建议

1. 管理员维护或选择受控词表。
2. 后台将词条文本向量与媒体向量比较，保存候选及模型代次。
3. 用户在资产或批量审核界面接受/忽略建议。
4. 接受动作调用既有手动标签服务；AI 建议删除或重建不会删除已确认标签。

### 人脸后台归类与用户建库

1. 后台检测人脸，过滤过小、严重遮挡或质量不足的裁剪，并先形成匿名聚类。
2. 人物页首先展示匿名组。用户选择一个组创建人物并填写名称；该组成员成为人物样本。
3. 后续匿名组可以整体合并到已有人物；低置信成员在合并前必须可预览和排除。
4. 单张图片可选择具体人脸并归入已有人物；系统保存人工 assignment。
5. 用户可移动错误成员、拆分聚类或排除某两张人脸属于同一人物；约束参与后续重聚类。
6. 模型可以推荐“可能属于人物 A”，但不能自动改写已命名人物边界。

### 模型获取与启用

1. 模型缺失时，管理员在“管理中心 → 智能功能 → 模型”查看 `/models` 离线目录状态。
2. 部署者把模型包放到宿主机目录，并以只读方式映射为容器 `/models`。管理员明确触发扫描；
   扫描只列出兼容清单中
   的包；未知文件显示“不兼容”，不解析为可执行扩展，也不交给推理运行时。
3. 默认选择“复制到托管目录”；复制成功后即使移除 `/models` 仍可运行。空间紧张时可明确选择
   “直接使用”，但必须持续保持只读、文件存在且哈希匹配。
4. 若直接使用的文件消失或变更，能力进入 unavailable，查询返回可解释错误；系统不删除现有索引、
   人物关系或人工标签。恢复相同哈希文件后可重新启用。
5. 选择另一兼容版本不会原地覆盖当前 generation；系统先并行建立并验证新索引，再切换激活版本。
6. revision 1 不显示在线下载或国内镜像入口；未来只有真实来源、运营与签名生命周期合同获批后
   才能新增。

## 关键产品规则

- `face observation`、匿名聚类和相似度是可重建派生状态；人物名称、人工 assignment、
  exclusion 和用户确认标签是应用状态，备份恢复必须保留。
- 同一图片可以有多个人脸；搜索人物时返回包含该人物 face assignment 的资产。
- 人工规则优先级高于模型结果：排除 > 人工归入 > 匿名聚类建议。
- 聚类是降低整理成本的建议，不是身份事实。UI 禁止使用“已识别为”描述自动结果。
- 人物命名允许重名；内部以 opaque person ID 区分，不把名称当唯一身份键。
- 按库启用和删除；跨库人物是否共用在 S1 前冻结。当前建议人物库为实例级、face 数据仍按库隔离。
- `/models` 是可选的只读模型来源，不是媒体库，也不受媒体目录浏览 API 管理；`/app/data/models`
  是 FolioPath 托管模型的唯一可写位置。
- “国内镜像”不是界面文案即可兑现的能力。只有项目或部署者实际提供经过签名清单约束的可达镜像，
  界面才显示该来源；没有镜像基础设施时，离线映射目录是确定可行的替代路径。

## 暂定验收门槛（须由 spike 校准）

以下是决策门槛，不是已证实性能：

| 维度 | 暂定门槛 |
| --- | --- |
| 运行资源 | 4 GiB 环境整进程 RSS 不超过 3.2 GiB；AI 并发默认 1；交互浏览 P95 退化不超过 20% |
| 首次处理 | 10 万图片 CPU 初次 embedding 在 24 小时内完成，支持重启续跑 |
| 语义查询 | 10 万媒体 P95 ≤ 750 ms、P99 ≤ 1.5 s；自有评测集 Top-20 命中率 ≥ 85% |
| 视频检索 | 人工标注视频查询 Top-20 命中率 ≥ 80%，无额外抽帧风暴 |
| 标签建议 | 审核集 Top-5 precision ≥ 75%；默认不自动写入 |
| 人脸聚类 | 可供整组建库的核心簇 precision ≥ 99.5%；未达标则只显示 pair/小组建议 |
| 磁盘 | 10 万媒体全部智能派生增量 ≤ 500 MiB，不含模型文件；超限须另行批准 |
| 模型获取 | 断点续传/取消/重启收敛；损坏、截断、错架构、错哈希、磁盘满和未知模型全部失败关闭 |
| 离线安装 | 无外网环境可从 `/models:ro` 完成扫描、托管复制或直接启用；不得读取任意其他路径 |
| 供应链 | 未签名/过期/撤回清单、未知包、重定向越界和许可证不允许分发均不得安装；无“仍然使用”绕过 |
| 人工约束 | 被明确排除的 face pair 在相同或后续 generation 中不得再次自动合并 |

## 交付顺序与 Gate

1. `INT-S0 Architecture Ready`：完成三个 spike、许可证审查、模型/索引/资源选择和隐私评审。
2. `INT-S1 Contract Ready`：冻结 A+B 的需求、OpenAPI、data/migration、错误、删除和升级语义。
3. `INT-S2 Backend Evidence Ready`：只交付 A+B 模型管理和图片语义检索；C/D/E 必须先有新的 Frozen
   scope revision 与独立 Gate。
4. `INT-S3 Consumer/UI Ready`：生产前端只消费已通过 S2 的合同；完成状态、纠错、双语、键盘和隐私说明。
5. `INT-S4 Integrated Slice Done`：真实单容器、目标容量、备份恢复、升级/回滚和原媒体不变证据齐全。
