# FTR-INT-001：智能媒体发现候选能力

## 状态与归属

- 状态：Future Candidate / 需求验证
- 目标版本：未排期的 Post-MVP；不属于 `MVP-2026-07-23`、`POST-MVP-1` 或
  `POST-MVP-2`
- 当前阶段：上线后需求观察；不授权 spike、生产合同或实现
- 产品负责人：产品用户
- 技术负责人：FolioPath maintainers
- 运行时 Capability Owner：尚未分配；必须在各子能力的 S0 Architecture Ready 中唯一确定
- 关联边界：`MVP-NG-004`、`internal/jobs`、`internal/catalog`、`internal/media`、
  `internal/files`

## 产品决定

OCR、AI 语义搜索和人脸识别不是被永久排除的能力。它们保留为 FolioPath 上线后的候选
feature，只有出现可验证的用户需求、完成资源与隐私评估，并通过独立交付 Gate 后才进入
排期。

当前决定不改变冻结的 MVP 范围，也不要求为了未来能力提前引入模型服务、向量数据库、
GPU 运行时、独立 worker 或新的部署单元。

## 候选顺序

顺序是当前产品建议，不是发布承诺；实际优先级由上线后的需求证据决定。

### 1. OCR 文字识别

候选价值：

- 搜索截图、票据、证件、文档照片和画面中的可见文字；
- 在现有文件名、路径搜索之外提供新的发现入口；
- 可作为相对独立的派生索引验证任务中心、模型版本和重新索引流程。

进入 S0 前至少需要确认：

- 目标语言、竖排文字、旋转图片和视频帧是否属于范围；
- OCR 文本的搜索、展示、纠错和清除行为；
- 对敏感文字、证件和个人信息的存储与诊断导出边界；
- CPU、内存、耗时和目标设备容量预算。

### 2. AI 语义搜索

候选价值：

- 支持使用自然语言按场景、物体、活动或视觉概念发现媒体；
- 与现有目录、媒体库、类型和时间筛选组合，而不是替代文件夹语义；
- 可以复用统一任务中心展示等待、生成、失败、取消和重建状态。

进入 S0 前至少需要确认：

- 本地模型、外部模型或可插拔 provider 的隐私与部署选择；
- embedding 模型版本、向量维度、索引迁移和跨版本不可比较问题；
- 是否使用 SQLite 扩展，以及容量、查询延迟和备份恢复影响；
- 查询文本、向量和模型输出是否进入日志、诊断包或遥测。

### 3. 人脸识别

候选价值：

- 在用户明确需要时，支持按人物聚合和查找家庭影像；
- 允许管理员合并、拆分、命名或清除人物派生数据；
- 人脸任务失败不影响普通浏览、搜索和最后可靠媒体索引。

进入 S0 前至少需要确认：

- 人脸检测、聚类、识别和人物命名各自的产品边界；
- 生物特征数据的告知、同意、按媒体库启用、清除、备份和迁移语义；
- 未成年人、访客和共享媒体库的隐私风险；
- 错误合并、错误识别、模型偏差和人工纠正流程。

人脸识别是三项候选中隐私和产品风险最高的一项，默认在 OCR 与语义搜索之后评估。

## 共同产品与安全不变量

- 三项能力默认关闭，并允许按媒体库独立启用；未启用时不生成对应派生数据。
- 原始媒体始终只读。模型不得写入 EXIF、重命名文件、移动目录或修改媒体字节。
- OCR 文本、embedding、人脸框、人物聚类和模型中间结果都是 `/app/data` 下的派生状态，
  必须可删除、可重建，并明确是否进入应用数据备份。
- 模型版本、输入源指纹、变换版本和输出 schema 必须参与派生数据身份；升级后不能静默复用
  不兼容结果。
- 所有生成与重建任务复用统一的有界全局队列、超时、取消、重试和公平性规则；普通浏览、
  poster 和缩略图不得被智能任务无限阻塞。
- 必须为 CPU、内存、磁盘和可选 GPU 设置硬上限。没有资源证据时失败关闭，不以无界并发
  换取首次处理速度。
- 离线、部分不可读、任务失败或模型不可用必须保留现有媒体索引和已验证的派生结果。
- API 只接受媒体库 ID、媒体 ID 和相对范围，不接受任意绝对路径；实际媒体读取继续通过
  `internal/files` 的 Linux 安全边界。
- 任何外部模型或网络传输都需要单独的信任边界、数据披露、安全和部署决定；不得作为隐藏
  默认行为。
- 清除入口必须区分“删除智能派生数据”和“删除原始媒体”，后者永远不是这些 feature 的
  能力。

## 交付 Gate

每一项候选能力都必须独立通过以下阶段，不允许以本文件直接开始生产实现：

1. **Demand Validation**：记录真实用户问题、使用场景、接受的隐私/资源代价和不采用时的
   影响。
2. **S0 Architecture Ready**：确定唯一 capability owner、模型/provider、持久化、任务、
   备份恢复、升级和部署影响；涉及新技术或信任边界时先接受 ADR。
3. **S1 Contract Ready**：接受需求 ID、OpenAPI、数据 schema、模型版本、删除/重建和错误
   语义。
4. **S2 Backend Evidence Ready**：在合成媒体上验证安全读取、资源上限、取消恢复、模型升级、
   损坏输入和目标容量。
5. **S3 Consumer/UI Ready**：实现按媒体库启用、进度、失败、清除、隐私说明、键盘和多语言
   行为，不在 UI 中承诺后端未提供的能力。
6. **S4 Integrated Slice Done**：真实容器纵向验证并确认禁用时零后台开销、模型不可用时普通
   浏览不退化。

## 明确的当前非目标

- 不把这三项加入当前管理原型的可用菜单或假装已经实现。
- 不提前选择模型、向量数据库、GPU 镜像或云服务。
- 不把重复检测、对象识别、自动标签、内容审核或生成式编辑自动并入本 feature。
- 不用智能索引替代文件系统层级、完整扫描或普通文件名/路径搜索。

## 后续触发条件

FolioPath 稳定上线后，如果用户反馈明确指向“照片中有文字但找不到”“无法用自然语言找到
场景”或“需要按人物整理家庭影像”，产品负责人可选择其中一项建立独立 Change Record 和
scope manifest。没有该决定时，本文件保持 Future Candidate 状态。
